# 아덴의 그림자

캐고, 만들고, 싸우고, 닳으면 다시 만드는 **스킬 기반 샌드박스 RPG**. 혼자서, 브라우저에서, 설치 없이.

▶ **[플레이하기](https://tepalmafia.github.io/my-web-game/)**

**레벨이 없습니다. 직업도 없습니다. 강화도 없습니다.**
곡괭이를 휘두르면 채광이 늘고, 망치를 두드리면 대장기술이 늡니다. 그게 전부입니다.

---

## 어떤 게임인가

한 바퀴는 이렇게 돕니다.

> 광맥을 캔다 → **짐이 무거워 발이 묶인다** → 마을로 걸어온다 → 화로에 녹인다 →
> 물건을 만든다 → 그걸 들고 사냥한다 → **닳는다** → 고치거나 새로 만든다 → 쇠가 떨어진다 → 다시 광산으로

이 고리를 닫는 규칙은 세 개뿐입니다.

| | |
|---|---|
| **무게** | 광석은 무겁고(10 스톤) 녹인 주괴는 가볍습니다(1 스톤). 소지 상한은 `힘 × 3.5 + 55`. 절반을 넘으면 최대 40%까지 느려집니다. "몇 덩이까지 지고 갈까"를 광맥 앞에서 계속 재게 됩니다 |
| **내구도** | 휘두르면 닳습니다. 수리하면 채워지지만 **최대 내구도가 12% 깎입니다.** 여덟 번쯤 고치면 더는 고칠 수 없는 쇳조각이 됩니다. 그래서 대장간에 다시 갈 이유가 사라지지 않습니다 |
| **스킬** | 성공해도 실패해도 오릅니다. 대신 **너무 쉬운 일로는 한 점도 오르지 않습니다.** 늘 조금 어려운 쪽으로 가게 만드는 곡선입니다 |

| | |
|---|---|
| **스킬 넷** | 채광 · 대장기술 · 검술 · 방어 (각 0.0 ~ 100.0) |
| **총합 상한** | 채광 + 대장기술 + 검술이 합쳐서 **400** 을 넘지 못합니다. 넘어서 안 오르고, 줄지도 않습니다. 무엇에 몰지가 이 인물을 정합니다. 방어는 총합에 안 들어갑니다 — 맞아봐야 아는 것이라 내가 고른 일이 아니기 때문입니다 |
| **시작 자리 셋** | 광부 · 견습 대장장이 · 떠돌이 경비병. 직업이 아니라 **첫 스킬 몇 점**만 다릅니다. 광부로 시작해 검사가 되어도 됩니다 |
| **지역 셋** | 실버우드 마을(화로·상점) → 초록 숲 → 버려진 광산. 안으로 갈수록 광석이 좋아지고 그만큼 위험합니다 |
| **품질** | 실력이 난이도보다 한참 높으면 **우수품**이 나옵니다. 성능도 수명도 더 좋습니다 |
| **죽음** | 골드 10%만 잃습니다. **배운 것은 그대로입니다** |

상점은 만든 무기와 갑옷을 팔지 않습니다 — 연장과 물약, 그리고 첫 녹슨 검 한 자루까지가 상점의 몫입니다.

조작은 마우스 하나로 끝납니다. 땅을 누르면 걷고, 바위에 비치는 광맥을 누르면 걸어가 캐고,
몬스터를 누르면 다가가 때립니다. S·I·C 로 실력·가방·대장간, Q 로 물약.
기록은 브라우저에 저장되고, 텍스트로 내보내 다른 기기로 옮길 수 있습니다.

"오늘 뭘 할까"를 정해주는 퀘스트도, 도달할 만렙도 없습니다. 그건 하는 사람이 정합니다.

## 화면은 어떻게 그리는가

그림 파일을 한 장도 쓰지 않습니다. 캐릭터도 나무도 용도 전부 도형으로 그립니다.
대신 흩어지지 않도록 규칙을 두 개만 지킵니다.

- **빛은 언제나 왼쪽 위에서 옵니다.** 갑옷이든 바위든 왼쪽 위가 밝고 오른쪽 아래에 그림자가 깔립니다.
  이것 하나로 서로 다른 도형들이 한 세계에 있는 것처럼 보입니다.
- **지역마다 공기색이 있습니다.** 초원은 초록과 금빛, 광산은 차가운 청록, 둥지는 재와 용암.
  같은 몬스터라도 그 지역의 색이 옅게 덮여 한 화면으로 묶입니다.

| 위치 | 역할 |
|---|---|
| `src/rpg/ui/art/palette.ts` | 지역별 색, 빛의 방향, 장비 재질. **색을 바꾸려면 여기만** |
| `src/rpg/ui/art/terrain.ts` | 바닥·물·벽·나무·빛·떠다니는 것 |
| `src/rpg/ui/art/actors.ts` | 캐릭터와 몬스터 |
| `src/rpg/ui/art/effects.ts` | 칼자국·화살·숫자·이름표 |
| `src/rpg/rpg.css` | 창의 재질 — 가죽 판, 놋쇠 테두리, 홈이 파인 막대 |

**입은 것이 그대로 보입니다.** 무기의 재질(녹슨 쇠·철·구리), 갑옷의 재질(가죽·사슬),
투구의 유무가 캐릭터 그림에 반영됩니다. 닳은 물건은 날이 상해 보입니다.

**깊이가 있습니다.** 나무와 캐릭터를 y좌표 순으로 섞어 그려서, 나무 뒤로 걸어 들어가면 가려집니다.
바닥과 벽은 지역에 들어갈 때 한 장으로 그려두고 재사용하므로 매 프레임 다시 칠하지 않습니다.

## 만들면서 정한 것

숫자를 만지는 사람과 코드를 만지는 사람이 서로를 방해하지 않도록 경계를 나눴습니다.

| 위치 | 역할 |
|---|---|
| `src/rpg/types.ts` | 게임에 존재하는 모든 정보의 형태. **동결** — 새 개념이 생길 때만 바뀝니다 |
| `src/rpg/balance.ts` | **조절 가능한 모든 숫자.** 난이도를 바꾸려면 이 파일만 고치면 됩니다 |
| `src/rpg/content/` | 아이템·몬스터·지역·광맥·제작법·스킬 목록. 표만 있고 계산은 없습니다 |
| `src/rpg/core/` | 규칙 — 캐기와 만들기, 전투, 이동과 지형, 내구도, 스킬 성장, 저장 |
| `src/rpg/ui/` | 화면. 게임 규칙을 스스로 판단하지 않고 `core/` 의 함수를 부르기만 합니다 |

**계산해서 알 수 있는 값은 저장하지 않습니다.** 최대 체력, 공격력, 소지 상한은 능력치와 장비에서
매번 다시 구합니다. 한 번 저장해두면 장비를 바꿨을 때 실제 값과 어긋나는 버그가 반드시 생깁니다.

**지형도 저장하지 않습니다.** 지역마다 정해진 씨앗으로 그때그때 만들어내며, 같은 씨앗이면 언제나
같은 지도가 나옵니다. 만든 뒤에는 입구에서 모든 문까지 실제로 걸어갈 수 있는지 확인하고,
닿지 않는 구덩이는 아예 막아버립니다 — 거기 태어난 몬스터는 영영 잡을 수 없기 때문입니다.

## 어떻게 확인하는가

화면을 눌러보지 않고도 규칙이 맞는지 알 수 있어야 합니다. 그래서 검사가 두 겹입니다.

### 1. 테스트 — `npm test` (134개, 3초)

```bash
npm test           # 한 번 돌리기
npm run test:watch # 고칠 때마다 자동으로
npm run check      # 타입검사까지 함께
```

| 파일 | 무엇을 지키는가 |
|---|---|
| `content.test.ts` | 표의 오타. 난이도 사다리가 100 까지 이어지는지. **시작 장비를 걸치고도 광석을 여러 덩이 질 수 있는지** |
| `skillgain.test.ts` | 성장 곡선. 쉬운 일로는 오르지 않는지, 100 에 도달은 가능한지, 능력치 합계 상한과 위축 |
| `action.test.ts` | 캐기·제련·제작·수리. **캐고 → 녹이고 → 만들면 검이 손에 들어오는지** |
| `world.test.ts` | 만들어진 지도에 걸어서 닿지 않는 칸이 없는지. 길찾기가 벽을 뚫지 않는지 |
| `combat.test.ts` | 명중·피해·내구도 소모. **계속 맞으면 결국 쓰러지는지** |
| `inventory.test.ts` | 무게. **입은 물건의 무게가 사라지지 않는지**. 상점에 무한 돈벌이가 없는지 |
| `save.test.ts` | 저장한 게 그대로 돌아오는지. 기록이 깨져 있어도 게임이 멈추지 않는지 |
| `loop.test.ts` | 봇을 20분 돌려 **한 바퀴가 실제로 도는지**, 그리고 제자리를 맴돌지 않는지 |

풀 리퀘스트를 올리면 GitHub Actions 가 이 셋(타입검사·테스트·빌드)을 자동으로 돌립니다.

> 이 테스트로 실제로 잡은 버그: **입은 장비의 무게가 0 이었던 것**(가방에서 빼면서 개수가 0 이 된 물건을
> 그대로 입혔습니다 — 이 게임의 뼈대인 무게 규칙이 통째로 죽어 있었습니다), 그리고 **아무리 맞아도
> 죽지 않던 것**(체력을 0 에서 붙잡아 두는 사이 자연 회복이 1 이상으로 끌어올려 죽음 판정이
> 걸리지 않았습니다).

### 2. 봇 — 몇 시간 치를 몇 초에

난수에 씨앗이 있어서 같은 판을 그대로 재현할 수 있습니다. 밸런스는 눈이 아니라 이걸로 맞췄습니다.

```bash
npx esbuild tools/sim.ts --bundle --format=esm --platform=node --outfile=/tmp/sim.mjs
node /tmp/sim.mjs smith 3 balanced     # 견습 대장장이로 3시간, 한 바퀴 전체
node /tmp/sim.mjs miner 2 mine         # 채광 곡선만
node /tmp/sim.mjs guard 2 fight x 42   # 전투 곡선만, 씨앗 지정
node /tmp/sim.mjs smith 1 balanced trace  # 목표가 바뀔 때마다 찍어보기
```

실측치(씨앗 5~6개): 첫 철검 **19~36분** · 채광 50 **64~83분** · 한 바퀴 완결 **2~4분** ·
철검 한 자루 수명 **90~111마리** · 14시간에 채광 80.4.

## 난이도 조절

`src/rpg/balance.ts` 하나만 열면 됩니다. 자주 만지게 될 값들:

| 값 | 효과 |
|---|---|
| `GAIN` | 스킬이 얼마나 빨리 느는가. 이 게임의 속도를 정하는 표입니다 |
| `WEIGHT` | 얼마나 자주 마을로 돌아와야 하는가 |
| `DURABILITY` | 만든 물건이 얼마나 오래 가는가 (`repairCost` 가 수리 한 번의 대가) |
| `GATHER` · `CRAFT` | 캐고 만드는 성공 확률 |

몬스터는 `src/rpg/content/monsters.ts`, 광맥은 `veins.ts`, 제작법은 `recipes.ts`,
아이템 무게와 값은 `items.ts` 에 있습니다.

## 같이 들어 있는 다른 게임 — AGI 경주

▶ **[플레이하기](https://tepalmafia.github.io/my-web-game/agi-race.html)** · 코드는 `src/` 바로 아래에 있습니다.

데이터센터를 짓고 GPU와 전력을 확보해, 경쟁 연구소 세 곳보다 먼저 AGI에 도달하면 이기는
경영 시뮬레이션입니다. 한 판 25분. 영어/한국어를 지원합니다.

- **투자를 받으면 지분이 줄어듭니다.** 일곱 번쯤 받으면 더 내줄 지분이 없습니다.
- **GPU는 전력이 있어야 돕니다.** 전력 계약을 잊고 GPU만 사면 산 만큼 그대로 놀립니다.
- **안전 검증을 건너뛰면 빨라집니다.** 대신 사고가 나면 그 자리에서 패배합니다.
- **진행도 45%를 넘으면 모델이 스스로 연구를 돕기 시작하고**, 그때부터 질문이
  "무엇을 살까"에서 "가속 ↔ 정렬 중 어디에 쓸까"로 바뀝니다.

이쪽 숫자는 `src/balance.ts`, 규칙은 `src/constraints/` 와 `src/state/` 에 있습니다.

## 직접 돌려보기

```bash
npm install
npm run dev        # 개발 서버 — / 는 RPG, /agi-race.html 은 AGI 경주
npm test           # 테스트 134개
npm run check      # 타입검사 + 테스트
npm run build      # 타입검사 + 두 게임 모두 빌드
```

`main` 에 푸시하면 GitHub Actions 가 빌드해서 GitHub Pages 에 자동 배포합니다.
