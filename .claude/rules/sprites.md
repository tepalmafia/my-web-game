# 그림 파일 규칙

`public/props/` 의 png 와 그것을 뽑는 `tools/` 에 걸린다.
왜 이렇게 정해졌는지는 `docs/그림-작업.md` 에 실측과 함께 있다.

## 1. 없으면 도형으로 떨어진다

`sprites.ts` 의 표에 줄을 넣으면 그림이 되고, 없으면 예전 도형이 그대로 나온다.
**한 장씩 켜고 끌 수 있어야 한다.**

| 갈래 | 키 | 없으면 |
|---|---|---|
| 장애물 | `<테마>/<종류>` — `forest/tree` · `cave/rock` | `<종류>` → 도형 |
| 광맥 | `vein/<id>` · 바닥나면 `vein/empty` | `vein` → 도형 |
| 몬스터 | `monster/<id>` | `shape/<모양>` → 도형 |
| 걷기 | `SPRITE_WALK` 의 같은 키 | 정지 한 장 |

테마는 `town` · `forest` · `cave` · `river` 넷.
화면에 실제로 나오는 장애물은 여덟뿐이다 —
`tree` `pine` `bush` `rock` `spire` `beam` `deadbush` `crystal`.

**로딩 실패를 조용히 삼키지 마라.** `drawImage` 에 아직 안 받아진 이미지를 넣으면
브라우저가 예외도 로그도 없이 아무것도 안 그린다. `spriteFor` 가 그것을 막는 장치다.

## 2. 뽑는 법 — 순서가 있다

```
node tools/gen-art.mjs rest <기준> --pixflux    # 또는 gen-frames.mjs
node tools/outline-art.mjs <이름조각>            # 윤곽선을 100% 로
node tools/trim-art.mjs <이름조각>               # 정지 한 장짜리
node tools/align-frames.mjs <이름>               # 걷기 프레임 — trim 대신 이것
node tools/measure-art.mjs                       # 재서 확인
```

**세 도구를 다 지나야 한다.** 하나라도 빼면 화면에서 티가 난다.

## 3. 팔레트 — `color_image` 로 강제한다

팔레트 그림을 넣으면 **정확히 그 색만** 나온다. 색이 154개에서 4~7개로 떨어졌다.

- **지역 팔레트 넷을 한 그림에 같이 넣지 마라.** 강제되는 값이라
  넷을 다 넣으면 광산 바위에 숲 초록이 들어간다
- 색은 상상하지 말고 **코드에서 가져온다** (`MATERIAL` · `IRON` · `SKIN` · `monsters.ts`)
- 밝은 면·어두운 면은 `actors.ts` 의 `shades()` 와 같은 식 — `lighten .3` / `darken .42`

| 지역 | 밝은 면 / 중간 / 어두운 면 |
|---|---|
| 마을 | `#4e7440` / `#2f5233` / `#1d3722` |
| 숲 | `#456e39` / `#2b4a2c` / `#19311e` |
| 광산 | `#544c60` / `#3a3442` / `#221d2a` — 보랏빛. **초록 이끼 금지** |
| 강가 | `#8a9463` / `#5e6a43` / `#39422a` |

**여러 몬스터가 나눠 쓰는 그림은 색을 굽지 마라.** 7종이 모양 3개에 얹혀 있어서,
색을 구우면 종류마다 그림이 필요하다. `SPRITE_TONES` 에 구워진 세 톤을 적어두면
`tintedSprite` 가 `def.color` 로 갈아끼운다. **윤곽선은 그 표에 없어서 안 물든다.**

## 4. 윤곽선 · 발밑 · 크기

- **윤곽선은 `#1b1613`, 가장자리 한 칸.** 뽑을 때 다 안 들어와서 코드로 채운다.
  알파를 안 건드리고 색만 바꾸므로 **두 번 돌려도 안 두꺼워진다**
- **그림의 아래 끝이 발밑이다.** PixelLab 은 가운데로 맞추므로 아래 여백을 잘라야 한다
- **3배로 뽑는다.** 최대 확대가 2.75배(zoom 1.375 × dpr 2)라 3배면 언제나 축소만 된다
- 배경은 투명. 회전하는 것은 정사각 여백

## 5. 걷기 프레임

- **한 창이 정확히 3프레임이다.** 창을 이어붙이면 튄다 —
  같은 관절을 두 창에 줘도 29.8% 다르게 나오고 발밑이 4px 어긋난다
- 그래서 **0 → 1 → 2 → 1 되짚기**로 네 박자를 만든다 (`WALK_ORDER`)
- **세 장의 크기가 같아야 한다.** `drawSprite` 가 가로만 받고 세로를 비율로 내므로,
  장마다 높이가 다르면 걷는 것이 아니라 커졌다 작아졌다 한다
- `trim-art.mjs` 를 프레임에 쓰지 마라. 장마다 따로 자른다.
  **`align-frames.mjs`** 가 아래끝을 맞춰 밀고 **하나의 사각형**으로 자른다
- 관절의 y 를 프레임마다 같게 주면 모델이 거의 안 흔든다

## 6. 못 하는 것 (재봤다)

- **부위만 못 뽑는다.** 몸통만(머리·다리 없음) 넣어도 통짜 인물이 나온다.
  갑옷 4 × 투구 3 × 무기 25 구조는 이 도구로 못 간다
- `animate_with_text` 는 **64×64 하나뿐**이라 원본(200×176)이 안 든다.
  `animate_with_skeleton` 은 256 까지 받는다
- `estimate_skeleton` 은 `z_index` 를 소수로 주는데 `animate` 는 정수만 받는다.
  그대로 넘기면 422 다

## 7. 새 콘텐츠를 언제 이미지로 만드는가 — 순서

**완성판에서 실제 플레이 화면에 남는 몬스터·NPC·랜드마크·아이템·환경물은
원칙적으로 이미지 자산을 쓴다.** 도형은 **개발용 임시본**과
**이미지 로딩 실패 시 폴백**으로 남긴다 (1절).

### 7.1 새로운 플레이 문법을 가진 콘텐츠 — 그림부터 만들지 않는다

```
기획 → 도형이나 기존 폴백으로 구현 → 실제 플레이 검증
     → 살릴 콘텐츠 확정 → 이미지 제작 → 스프라이트 적용
     → 실제 게임 크기로 검증
```

**새 몬스터 행동 · 새 맵 구조 · 새 흔적 자리는 반드시 임시본 검증을 먼저 한다.**

### 7.2 이미 검증된 문법의 반복 자산 — 바로 이미지로 간다

예 — 기존 광맥 시스템에 새 광석 종류를 더하는 경우.

### 7.3 전체 맵을 한 장의 이미지로 만들지 않는다

맵은 **타일 · 프롭 · 랜드마크 · 상태별 스프라이트를 조합**한다.
**큰 구조는 게임 데이터가 정하고 그림은 그 결과를 그린다** (CLAUDE.md 4장, 5장).

### 7.4 영구 변화가 있는 환경물은 필요하면 상태별 이미지를 둔다

쓰러진 나무 → 벤 그루터기. 무너진 다리 → 고친 다리.
**이미지가 없어도 도형 폴백으로 플레이가 되어야 한다.**

### 7.5 만들기 전에 — 그 콘텐츠가 실제로 새로운 판단을 만드는가

**체력·색·수치만 다른 콘텐츠에는 새 이미지를 먼저 만들지 않는다.**
