# 그리는 쪽 규칙

`src/rpg/ui/` · `src/rpg/dev/` 에 걸린다. 세계의 규칙(core)과 표(content)는 여기 없다.

## 1. 좌표는 세계에서 받는다 — 화면 픽셀로 역추적하지 마라

**이것이 이 파일에서 제일 중요한 줄이다.**

무엇이 화면 어디에 있는지 알아야 할 때, **색이나 그림자로 되짚지 마라.**
세 번 틀렸다.

| 시도한 것 | 왜 틀렸나 |
|---|---|
| 살색 `#e8b98c` 을 찾는다 | 안개와 공기색이 `overlay` 로 덮여 픽셀 값이 달라진다 |
| 그림자 반지름으로 찾는다 | 식이 `r*0.42` 인데 `r*0.45` 로 봤다 |
| 몸통 색으로 찾는다 | 갑옷 재질마다 다르고 `fine` 이면 또 다르다 |

**대신 `window.aden.inspect()` 를 쓴다** (`src/rpg/dev/inspect.ts`).
player · camera · monsters · view 를 숫자로 돌려주고, 화면 좌표는
렌더러가 쓰는 것과 **같은 함수**(`computeView` + `snapView`)로 낸다.
읽기 전용이고 프로덕션 빌드에 안 들어간다.

```js
const s = window.aden.inspect();
s.player.screen        // 캔버스 CSS 픽셀
s.camera.step          // zoom × dpr — 격자를 맞출 때 쓰는 값
s.monsters[0].anim     // 걸음 위상
```

**변환식을 두 벌 쓰지 마라.** 재는 쪽이 식을 다시 쓰면 그리는 자리와 갈라진다.

## 2. 격자

- 카메라는 `view.ts` 의 `snapView` 가 화면 픽셀에 맞춘다.
  **`GameScreen` · `draw` · `kick` 셋이 같은 `dpr` 을 봐야 한다** — 하나라도 소수가 남으면 헛일이다
- 그림은 `sprites.ts` 의 `drawSprite` 가 맞춘다. **월드 좌표에서 반올림하면 안 된다** —
  `zoom × dpr` 을 곱한 뒤 화면 픽셀 자리에서 맞추고 되돌린다
- 돌아간 변환(쓰러지는 몬스터)에서는 안 맞춘다. 기울어진 것을 격자에 맞추는 것은 뜻이 없다
- `imageSmoothingEnabled` 는 꺼 둔다

## 3. 그림자 · 앵커 · 빛

**그림자는 코드가 그린다. 그림에 굽지 마라.** 구우면 둘이 되고 방향이 어긋난다.

| | 어디 | 값 |
|---|---|---|
| 프롭 그림자 | `terrain.ts` `drawProp` | `cx+3, cy+TILE*0.34` 타원 |
| 사람·몬스터 그림자 | `actors.ts` `drawShadow` | `ellipse(x + r*0.16, y, r, r*0.42)` |
| 프롭 접지선 | `terrain.ts` | 타일 위 **0.72** (`draw.ts` 의 깊이 정렬과 같은 값) |
| 사람 발밑 | `actors.ts` | `y + 11`, 그림자 반지름 12 |
| 몬스터 발밑 | `actors.ts` | `y + size*0.78`, 그림자 반지름 `size*0.82` |
| 화로 | `effects.ts` | 중심 `+9` |

**빛은 언제나 왼쪽 위** — `palette.ts` 의 `LIGHT = {x:-0.55, y:-0.84}`, 약 123도.
**예외는 화로 하나**다. 아궁이 쪽이 밝다.

**좌우는 `scale(-1,1)` 로 통째 뒤집는다.** 8방향이 아니다 —
위/아래는 `facingUp` 이 무기 z순서·머리색·눈 셋만 바꾼다.
그래서 **한쪽에만 진한 하이라이트를 구우면 왼쪽을 볼 때 빛이 오른쪽에서 온다.**

## 4. 그리는 쪽은 규칙을 판단하지 않는다

세계를 바꾸는 것은 `core/commands.ts` 로만 한다.
읽는 것은 `core/` 의 함수를 부르되 **조건을 여기서 조립하지 않는다** —
「될까/왜 안 될까」의 답은 core 가 만들고 여기는 받아 그린다.

`core/` 는 `audio/` 와 `dev/` 를 모른다.

## 5. 애니메이션 — `anim` 은 그리기 전용이다

`monster.anim` · `world.meAnim` 은 **네 곳에서만 읽히고 전부 `actors.ts`** 다.
게임 규칙 어디에도 안 들어간다. 그래서 값을 바꿔도 봇 지표가 바뀌면 안 된다 —
바뀌면 그것은 버그다.

**도형 렌더러에는 딛는 발이 없다.** `walk` 가 다리 *높이*와 신발 *y* 에만 걸린다.
발이 가로로 안 움직이므로 **전진의 100% 가 미끄러짐**이고, `anim` 상수를
어떻게 바꿔도 그것은 안 줄어든다. 자세한 것은 `docs/그림-작업.md` 5.1.6.
