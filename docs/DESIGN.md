## 1. 이 게임의 한 바퀴

```
     광맥을 캔다 ──▶ 짐이 무거워진다 ──▶ 마을로 걸어온다
         ▲                                      │
         │                                 화로에서 녹인다
         │                                      │
    쇠가 떨어진다                            물건을 만든다
         │                                      │
         └──── 장비가 닳는다 ◀──── 사냥한다 ◀───┘
```

이 고리를 닫는 규칙은 **세 개**입니다.

1. **무게** — 광석은 무겁고(10 스톤) 주괴는 가볍습니다(1 스톤). 그래서 캘 때는 발이 묶이고, 녹이고 나면 가벼워집니다. 소지 상한 = `힘 × 3.5 + 55`. 상한의 절반을 넘으면 최대 40%까지 느려집니다.
2. **내구도** — 휘두르면 닳습니다(4 번에 1). 수리하면 채워지지만 **최대 내구도가 12% 깎입니다.** 여덟 번쯤 고치면 더는 고칠 수 없는 쇳조각이 됩니다.
3. **스킬은 시도할 때만 는다** — 성공해도 실패해도 오릅니다. 대신 **너무 쉬운 일(난이도 < 실력 − 20)로는 한 점도 오르지 않습니다.** 그래서 늘 조금 어려운 쪽으로 가게 됩니다.

---

## 2. 스킬 — 이 게임의 유일한 성장

네 개뿐입니다. **채광 · 대장기술 · 검술 · 방어.**

```
성장 확률 = 0.62 × max(0.035, (1 − 실력/100)^1.5) × exp(−(난이도 − 실력 − 5)² / (2 × 18²))
한 번 오를 때 0.18 점
```

- 난이도가 **실력 + 5** 일 때 가장 잘 오릅니다. 딱 그만큼 어려운 일을 찾아다니게 하려는 곡선입니다.
- `max(0.035, …)` 의 바닥값이 없으면 100 은 수학적으로 도달 불가능해집니다. 그래서 바닥을 둡니다.
- 실측: 채광 25 → 50 까지 **약 70분**(꾸준히 캘 때), 14시간을 캐면 80.4. **100 은 수십 시간짜리 목표입니다.**

### 능력치는 스킬을 따라옵니다

힘·민첩·지능은 직접 올리지 않습니다. 채광하면 힘이, 검술을 쓰면 민첩이 가끔 함께 오릅니다(시도당 5%).
개별 상한 100, **합계 상한 225** — 합계에 닿으면 가장 오래 안 쓴 능력치가 조금씩 빠집니다(위축).
합계 상한이 없으면 시간만 쓰면 모두가 힘 100 이 되어, 이 게임의 뼈대인 무게 제약이 녹아버립니다.

| | 수 | 내용 |

| 지역 | 3 | 실버우드 마을(안전·화로·상점) → 초록 숲 → 버려진 광산. 한 줄로 이어짐 |

| 아이템 | 18 | 연장 2 · 자원 4 · 무기 5 · 갑옷 3 · 투구 2 · 물약 2 |
| 제작법 | 9 | 제련 2 + 무기 4 + 방어구 3. 난이도 10 → 88 로 이어져 대장기술 100 까지 배울 길이 있음 |

| 창 | 4 | 실력 · 가방 · 대장간 · 상점 |

**깊이가 곧 위험입니다.** 몬스터와 광맥은 입구로부터의 거리로 배치됩니다.
숲 안쪽에 늑대와 함께 깊은 철광맥이 있고, 광산 안쪽에 박쥐·거미와 함께 구리가 있습니다.
"위험한 곳에서 캘 것인가"가 채광의 진짜 질문이 되도록 한 배치입니다.

**상점은 만든 물건을 팔지 않습니다.** 연장·물약·녹슨 검 한 자루까지가 상점의 몫입니다.
그걸 팔기 시작하면 대장간에 갈 이유가 사라집니다.

## 4. 코드 구조 — 경계와 불변 규칙

```
src/rpg/
  types.ts        모든 정보의 형태. 새 개념이 생길 때만 바뀜
  balance.ts      조절 가능한 모든 숫자 — 성장·무게·내구도·전투·회복
  content/        표만 있고 계산은 없음 — items · monsters · maps · veins · recipes · skills
  core/           규칙
    world         지형 생성(씨앗) · 길찾기(BFS + 시야 당기기)
    engine        매 프레임 — 이동 · 행동 · 전투 · 몬스터 · 회복 · 문 · 죽음 판정
    action        캐기 · 만들기 · 고치기 (Phase 1 의 심장)
    skillgain     성장 굴림과 능력치 위축
    durability    닳음 · 연장 사용 · 수리 견적
    combat stats inventory commands death loot save create rng feedback
  ui/             화면. 규칙을 스스로 판단하지 않고 core/ 의 함수만 부름
    art/          palette · terrain · actors · effects — 이미지 파일 없이 전부 코드로 그림
tools/
  autopilot.ts    봇의 두뇌 (예전 runAuto 가 여기로 옮겨 왔습니다)
  sim.ts          몇 시간 치를 몇 초에 돌려 §7 지표를 재는 장치
tests/rpg/        8개 파일 134개
```

### 깨면 안 되는 다섯 가지

1. **계산할 수 있는 값은 저장하지 않는다** — 최대 체력·공격력·소지 상한은 전부 `derive()` 가 그때그때 만듭니다.
2. **지형을 저장하지 않는다** — 씨앗으로 다시 만듭니다. 저장 파일에는 사람과 시간과 씨앗만 들어갑니다.
3. **UI 는 규칙을 판단하지 않는다** — 화면은 `core/commands.ts` 만 부릅니다. "만들 수 있는가"는 core 가 답합니다.
4. **표(content)와 계산(logic)을 섞지 않는다** — 밸런스를 고치는 사람이 코드를 읽지 않아도 되도록.
5. **씨앗 난수를 유지한다** — 같은 씨앗이면 같은 세계가 나옵니다. 봇 실측이 재현 가능해야 하기 때문입니다.

## 5. 저장

`aden:v2:char:<id>:state` — 처음부터 이름칸을 둡니다. 지금은 하나뿐이지만 구조를 나중에 바꾸지 않기 위해서입니다.
저장하는 것은 **사람 · 지역 · 시간 · 다음 번호 · 씨앗** 뿐입니다. 지형·몬스터·광맥은 씨앗에서 다시 태어납니다.
텍스트로 내보내고(base64) 다시 불러오는 길도 있습니다 — 기기를 옮기거나 백업할 때 씁니다.

새로고침하면 제목 화면의 **이어서 하기**로 돌아옵니다. 다시 들어가면 그 지역 입구에서 시작합니다.

## 7. 실측 지표 (봇, 씨앗 5~6개)

`tools/sim.ts` 로 잰 값입니다. 지시서 §4.3 의 목표와 나란히 둡니다.

| 지표 | 목표 | 실측 | |
|---|---|---|---|
| 첫 철검 (견습 대장장이) | 15~25분 | **19 · 20 · 22 · 26 · 35 · 36분** (중앙값 24) | 대체로 ○ |
| 채광 50 (꾸준히 캘 때) | 약 60분 | **64 · 70 · 73 · 73 · 83분** (중앙값 73) | 조금 느림 |
| 한 바퀴 완결 | 30분 안에 1회 | **2.2 ~ 4.1분** | ○ |
| 철검 한 자루 수명 | 몬스터 80~120마리 | **90 · 98 · 111마리** (수리하며 쓰다 못 쓰게 될 때까지) | ○ |
| 채광 100 / 대장 100 | 실측만 | 14시간에 **채광 80.4 · 대장 59.4** | 수십 시간 |

여섯 시간 기준 사망 1~4회, 처치 380~410마리. 힘은 14시간이면 100 에 닿습니다(합계 172).

**첫 철검이 씨앗에 따라 19~36분으로 흔들리는 이유**: 철검(난이도 41)을 두드려 보려면 대장기술이 26 은 되어야 하고,
견습 대장장이는 24 로 시작합니다. 그 **두 점**을 제련으로 채우는 시간이 광맥 배치에 따라 달라집니다.
광석 하나가 곧 제련 한 번이므로, 대장기술은 광석을 캔 만큼 오릅니다.

## 8. 봇을 돌리는 법

```bash
npx esbuild tools/sim.ts --bundle --format=esm --platform=node --outfile=/tmp/sim.mjs
node /tmp/sim.mjs <시작자리> <시간> <초점> [trace] [씨앗]
node /tmp/sim.mjs smith 3 balanced          # 한 바퀴 전체
node /tmp/sim.mjs miner 2 mine              # 채광 곡선만
node /tmp/sim.mjs guard 2 fight x 42        # 전투 곡선만, 씨앗 지정
node /tmp/sim.mjs smith 1 balanced trace    # 목표가 바뀔 때마다 찍어보기
```

`trace` 는 밸런스보다 **봇이 제자리를 맴도는 고장**을 잡는 데 씁니다. 그 고장은 화면상 아무 일도 일어나지
않은 채 한 시간이 지나가서, 지표만 보고 있으면 원인을 찾는 데 아주 오래 걸립니다.
`tests/rpg/loop.test.ts` 가 그 맴돎을 자동으로 감시합니다.

## 9. 만들면서 밟은 지뢰 (다시 밟지 않기 위해)

- **입은 장비의 무게가 0 이었다.** `equip()` 이 가방에서 빼면서 개수를 0 으로 만든 물건을 그대로 입혔습니다. 이 게임의 뼈대인 무게 규칙이 통째로 죽어 있었습니다. → `tests/rpg/inventory.test.ts`
- **아무리 맞아도 죽지 않았다.** 피해 처리가 체력을 0 에서 붙잡아 두고, 그 사이 자연 회복이 1 이상으로 끌어올려서 죽음 판정이 걸리지 않았습니다. 봇 실측의 "사망 0회"가 이 고장이었습니다. → `tests/rpg/combat.test.ts`
- **되살아나는 시간이 13초였다.** 한 마리를 잡는 동안 다음 한 마리가 돌아와서, 광맥 옆에서 곡괭이를 들 틈이 없었습니다. 지금은 50~110초입니다.
- **검 한 자루가 40 스톤이었다.** 광부가 한 번에 광석 두 덩이밖에 못 지고 와서, 한 시간이 왕복으로만 갔습니다. 지금은 무거운 것이 광석뿐입니다.
- **봇이 마을에서 85%를 보냈다.** "검이 닳았다"만 보고 마을로 보냈는데, 돈도 쇠도 없으면 마을에서 할 수 있는 일이 없어서 무한히 맴돌았습니다. 같은 종류의 고장을 서로 다른 이유로 네 번 만났습니다(곡괭이·망치·여벌 검·짐). 지금은 **마을이 지금 고쳐줄 수 있는 일일 때만** 돌아갑니다.
