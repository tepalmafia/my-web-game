# 아덴의 그림자 — 설계 문서

> 브라우저에서 혼자 하는 리니지풍 RPG.
> **이 문서 하나만 읽으면 프로젝트 전체를 알 수 있도록** 정리했습니다 — 무엇을 만들었는지, 왜 그렇게 했는지,
> 무엇이 아직 없는지, 그리고 다음에 결정해야 할 것이 무엇인지.
>
> 기준 시점: 2026-08-19 · 코드 약 10,800줄 (게임 6,300 / 테스트 2,100 / 봇 220 / 나머지 UI)
> 플레이 방법과 사용법은 [README](../README.md) 를 보세요. 이 문서는 그 뒤의 이야기입니다.

## 1. 이 게임이 무엇인가

**핵심 루프**: 사냥터에서 몬스터를 잡는다 → 골드와 주문서가 모인다 → 장비를 산다 → **강화한다** → 더 위쪽 사냥터로 간다.

**게임의 중심은 레벨이 아니라 강화입니다.**

| 강화 수치 | +0→3 | +4 | +5 | +6 | +7 | +8 | +9 | +10 |
|---|---|---|---|---|---|---|---|---|
| 성공 확률 | 100% | 75% | 60% | 45% | 33% | 22% | 14% | 8% |

- **일반 마법 주문서**로 실패하면 그 장비는 그 자리에서 **부서져 사라집니다.** 되돌릴 방법 없음.
- **축복받은 주문서**는 실패해도 +0 으로 돌아갈 뿐. 대신 10배 이상 비쌉니다 (2,200 vs 28,000 골드).
- 무기 +1 당 피해 +9%. +7 짜리 무기 한 자루가 레벨 다섯보다 셉니다.
- 그래서 골드는 결국 전부 주문서로 갑니다. **이 게임의 감정선은 여기 하나에 걸려 있습니다.**

**조작**: 땅을 누르면 걷고, 몬스터를 누르면 다가가 자동으로 때립니다. 1·2·3 스킬, Q·W 물약, Space 자동 사냥.

## 3. 코드 구조 — 경계와 불변 규칙

```
src/rpg/
  types.ts        모든 정보의 형태 (568줄). 새 개념이 생길 때만 바뀜
  balance.ts      조절 가능한 모든 숫자 (220줄). 난이도는 여기만 고치면 됨
  content/        표만 있고 계산은 없음 — items · monsters · maps · skills · quests · classes
  core/           규칙 — world(지형·길찾기) engine(매 프레임) combat stats commands
                        enhance progression loot inventory quests save create rng feedback
  ui/             화면. 규칙을 스스로 판단하지 않고 core/ 의 함수를 부르기만 함
    art/          palette(색·빛) terrain(바닥·물·나무) actors(캐릭터·몬스터) effects(숫자·이름표)
    rpg.css       창의 재질 (가죽 판 · 놋쇠 테두리 · 홈 파인 막대)
tools/sim.ts      밸런스 확인용 봇 (게임에 포함되지 않음)
tests/rpg/        테스트 11개 파일 190개
```

**지키고 있는 규칙 네 가지** — 새 기능을 넣을 때 이걸 깨지 않는 게 중요합니다.

1. **계산해서 알 수 있는 값은 저장하지 않는다.** 최대 체력·공격력·AC 는 장비와 버프에서 매번 다시 구합니다(`derive()`). 저장하면 장비 교체 시 실제 값과 어긋납니다.
2. **지형도 저장하지 않는다.** 지역마다 정해진 씨앗으로 매번 생성하고, 만든 뒤 "입구에서 모든 문까지 걸어갈 수 있는가"를 확인해 닿지 않는 구덩이는 막아버립니다. 저장 파일에는 "지금 어느 지역인가" 한 줄만.
3. **화면은 규칙을 모른다.** UI 는 `core/commands.ts` 의 함수를 부를 뿐, "지금 쓸 수 있는가/얼마인가/왜 안 되는가"는 전부 core 가 판단합니다.
4. **난수에 씨앗이 있다.** 같은 씨앗이면 같은 판이 재현되므로 봇으로 몇 시간 치를 몇 초에 돌려볼 수 있습니다.

**그림 파일을 한 장도 쓰지 않습니다.** 캐릭터·몬스터·지형 전부 캔버스 도형. 대신 규칙 두 개로 묶습니다 — ① 빛은 언제나 왼쪽 위에서 온다 ② 지역마다 공기색이 있다. 장비(무기 계열·갑옷 재질·투구·강화 수치)가 캐릭터 그림에 그대로 반영되고, +7 이 넘으면 발밑이 빛납니다.

## 4. 밸런스 실측치 (봇 자동 사냥, 씨앗 고정)

| 직업 | 만렙(40) 도달 | 사망 | Lv.10 | Lv.20 | Lv.30 |
|---|---|---|---|---|---|
| 기사 | 2시간 33분 | 1회 | 14분 | 48분 | 94분 |
| 요정 | 2시간 8분 | 0회 | 12분 | 38분 | 68분 |
| 마법사 | 2시간 42분 | 0회 | 14분 | 55분 | 91분 |

**고룡 카르나스(Lv.40, 체력 32,000)**
- 전설 +7 장비 · Lv.34 → 144초, 물약 31병
- 희귀 +3 장비 · Lv.31 → 341초, 물약 173병 (약 7만 골드어치)
- 마법사가 희귀 +3 으로 도전 → **실패**. "더 갖춰서 오라"는 신호로 의도한 결과

한 레벨에 몬스터 35~50마리, 한 마리에 4~6초가 기준입니다. 30분 정도 놀면 15~18레벨.

## 5. 어떻게 검증하고 있나

- **테스트 190개 / 2초** (`npm test`). 표의 오타(없는 아이템을 떨구는 몬스터, 없는 지역으로 이어지는 문), 강화 확률과 실제 결과 일치(4,000회 표본), 축복 주문서가 장비를 남기는지(1,000회 실패), 지도에 걸어서 닿지 않는 칸이 없는지, 3분을 실제로 돌려 벽에 끼거나 좌표가 깨지지 않는지, 상점에 무한 돈벌이가 없는지.
- **CI**: PR 마다 타입검사 + 테스트 + 빌드 (`.github/workflows/ci.yml`).
- **봇**: `npx esbuild tools/sim.ts --bundle --format=esm --platform=node --outfile=/tmp/sim.mjs && node /tmp/sim.mjs knight 3`
- **브라우저**: Playwright 로 실제 플레이 + 스크린샷.

**테스트가 실제로 잡은 것 두 가지** (참고용 — 이런 종류의 버그가 나오는 프로젝트라는 뜻):
- 자동 사냥이 바위 뒤 몬스터로 직진하다 **150초 동안 멈춰 있던** 문제 → 길찾기(BFS) 도입, 3분 처치 수 2~47 → 50~61
- 보스를 조금씩 깎아놓고 죽기를 반복하면 **거저 잡히던** 문제 → 싸움이 끝난 몬스터는 체력 회복

## 6. 지금 없는 것 (정직하게)

**의도적으로 뺀 것**
- PvP·파티·거래·채팅 (혼자 하는 게임)
- 죽어도 아이템을 떨구지 않음 (리니지 원본은 떨굼)
- 퀘스트는 마을에 보고하러 갈 필요 없이 자리에서 자동 완료 (사냥 흐름을 끊지 않으려고)

**아직 못 넣은 것 / 빚**
- **소리가 전혀 없음.** 강화 파괴음 하나만 있어도 체감이 크게 달라질 자리
- **몬스터는 길찾기가 없음** (플레이어만 있음). 바위 뒤에서 맴돌 수 있음
- **지형 씨앗이 지역당 고정** → 매번 같은 지도
- **저장이 한 칸.** 다른 직업을 해보려면 기존 기록을 지워야 함. 내보내기/불러오기 없음
- **아이템에 랜덤 옵션이 없음.** 47개가 전부이고 등급은 고정. "더 좋은 걸 찾는" 축이 얕음
- **한국어 전용** (같은 저장소의 AGI 경주는 en/ko 지원)
- 아이템 툴팁/장비 비교 UI 없음, 접근성(키보드 전용·색약·스크린리더) 미검토
- 보스를 잡은 뒤의 **결과·공유 화면 없음** (AGI 경주에는 있었음)
- 플레이 링크(아티팩트) 빌드가 수동 단계

## 7. 열려 있는 설계 질문

아직 답을 정하지 못한 것들입니다. 만들면서 확신이 서지 않았던 지점만 골랐습니다.

**Q1. 자동 사냥이 게임을 갉아먹고 있는가?**
Space 한 번이면 이동·타격·물약·스킬을 전부 알아서 합니다. 편하지만 "클릭해서 노는 게임"의 긴장을 스스로 없앱니다. 지금은 보스만 제외. → 그대로 둘까 / 자동일 때 획득량을 깎을까 / 자동은 이동과 물약만 맡고 전투는 손으로 할까 / 아예 오프라인 보상으로 분리할까.

**Q2. 죽음이 너무 물렁한가?**
경험치 30% + 골드 8% 만 잃습니다. 강화 실패의 공포는 있는데 **사냥 중의 공포가 없습니다.** 봇 기준 3시간에 0~1회 사망. 아이템 드랍을 넣으면 리니지에 가까워지지만 혼자 하는 브라우저 게임에는 가혹할 수 있음.

**Q3. 만렙 다음에 무엇을 하는가?**
지금 엔드게임 = 고룡 반복 + 강화 도박. 아이템이 47개뿐이고 랜덤 옵션이 없어 금방 바닥이 보입니다. → 랜덤 접두사(마법 옵션) / 세트 효과 / 상위 사냥터 추가 / 주간 보스 / 캐릭터 여러 개 육성 중 무엇이 이 게임에 맞는가.

**Q4. 한 판의 길이가 브라우저 게임에 맞는가?**
봇 기준 만렙 2시간 30분, 사람은 4~5시간. 30분 세션이면 15~18레벨. MMO 식 장기 성장으로 갈지, 짧은 런(로그라이크)으로 재구성할지.

**Q5. 캐릭터를 여러 개 만들 수 있어야 하는가?**
직업이 셋인데 저장은 한 칸입니다. 다른 직업을 보려면 지금까지를 지워야 합니다.

**Q6. 소리를 넣는다면 어디까지?**
그림 파일을 안 쓰는 원칙과 맞추려면 WebAudio 합성. 타격·피격·레벨업·강화 성공/파괴 정도가 후보.

**Q7. 두 게임을 한 저장소에 두는 게 맞는가?**
`index.html` = RPG, `agi-race.html` = 기존 AGI 경주(25분짜리 경영 시뮬레이션). 빌드가 함께 나가고 배포도 한 곳입니다.

## 8. 제약 조건 (조언할 때 전제로 삼을 것)

- **정적 웹만.** 서버·데이터베이스·로그인 없음. GitHub Pages 에 배포
- **의존성 최소.** React + Vite + Tailwind + vitest 가 전부. 게임 엔진·물리 라이브러리 없음
- **그림/소리 파일 없음.** 전부 코드로 생성 (지금까지의 원칙)
- **휴대폰에서 돌아가야 함** (현재 390×844 에서 59 FPS)
- 기록은 브라우저 localStorage 단일 슬롯

## 9. 어디를 만지면 무엇이 바뀌는가

| 하고 싶은 것 | 고칠 파일 |
|---|---|
| 강화가 더/덜 잔인하게 | `balance.ts` → `ENHANCE_CHANCE` |
| 레벨업 속도 | `balance.ts` → `expToNextLevel()` |
| 죽음의 대가 | `balance.ts` → `DEATH` |
| 자동 사냥 판단 | `balance.ts` → `AUTO`, `core/engine.ts` → `runAuto()` |
| 몬스터 추가/조정 | `content/monsters.ts` (+ 지역 배치는 `content/maps.ts`) |
| 아이템 추가 | `content/items.ts` (상점 진열은 `SHOP_STOCK`) |
| 지역 추가 | `content/maps.ts` (지형은 씨앗으로 자동 생성) |
| 색·분위기 | `ui/art/palette.ts` |
| 창의 재질·글꼴 | `rpg/rpg.css` |
