# 아덴의 그림자 — 밟은 지뢰

> 다시 밟지 않으려고 적어둔다. **이 문서는 낡지 않는다** —
> 여기 적힌 것은 지금 게임이 어떻게 생겼는지가 아니라, 무엇이 어떻게 고장났었는지다.
>
> 원래 `docs/DESIGN.md` 9절이었다. 그 문서는 Phase 1 의 기록이라 전부 낡아 지웠고,
> 낡을 수 없는 이것만 남겼다.

---

## 규칙이 통째로 죽어 있었던 것

- **입은 장비의 무게가 0 이었다.** `equip()` 이 가방에서 빼면서 개수를 0 으로 만든 물건을
  그대로 입혔습니다. 이 게임의 뼈대인 무게 규칙이 통째로 죽어 있었습니다.
  → `tests/rpg/inventory.test.ts`

- **아무리 맞아도 죽지 않았다.** 피해 처리가 체력을 0 에서 붙잡아 두고, 그 사이 자연 회복이
  1 이상으로 끌어올려서 죽음 판정이 걸리지 않았습니다. 봇 실측의 "사망 0회" 가 이 고장이었습니다.
  → `tests/rpg/combat.test.ts`

## 수치 하나가 게임을 통째로 바꾼 것

- **되살아나는 시간이 13초였다.** 한 마리를 잡는 동안 다음 한 마리가 돌아와서,
  광맥 옆에서 곡괭이를 들 틈이 없었습니다. 지금은 50~110초입니다.

- **검 한 자루가 40 스톤이었다.** 광부가 한 번에 광석 두 덩이밖에 못 지고 와서,
  한 시간이 왕복으로만 갔습니다. 지금은 무거운 것이 광석뿐입니다.

## 같은 고장을 네 번 만난 것

- **봇이 마을에서 85%를 보냈다.** "검이 닳았다" 만 보고 마을로 보냈는데, 돈도 쇠도 없으면
  마을에서 할 수 있는 일이 없어서 무한히 맴돌았습니다. 같은 종류의 고장을 서로 다른 이유로
  **네 번** 만났습니다(곡괭이·망치·여벌 검·짐). 지금은 **마을이 지금 고쳐줄 수 있는 일일 때만**
  돌아갑니다. `tests/rpg/loop.test.ts` 가 그 맴돎을 감시합니다.

## 그 뒤에 밟은 것

- **`enterMap` 이 바닥을 비웠다.** 지역을 옮기는 순간 놓아둔 것이 사라져서,
  "돌아왔을 때 남아 있을까" 가 언제나 '아니오' 였습니다. 지금은 지역마다 갈무리합니다.

- **표에 없는 키를 조회하고 기본값으로 덮었다.** `MATERIAL[id] ?? 기본색` 이라
  가죽 조끼든 구리 사슬갑옷이든 전부 같은 회색으로 보였습니다. **없으면 기본값은 안전하지만,
  그래서 틀린 걸 아무도 모릅니다.** → `tests/rpg/art.test.ts`

- **`discovered` 를 아무도 안 읽었다.** `enterMap` 이 채우기만 했습니다.
  데이터가 있는데 화면에 없었습니다. → 칭호가 그것을 읽습니다.

- **씨앗을 안 박은 시험이 여섯 번에 한 번 깨졌다.** `createWorld` 가 `Date.now()` 로
  씨를 뿌리는데 시험이 그것을 안 박아서, 제작 성패가 매번 달라졌습니다.
  → 재현은 반드시 씨앗으로 (CLAUDE.md 7장)

- **조사를 문자열에 붙였다.** `「길 아는 사람」 라` — '사람' 뒤에는 '이라', '자' 뒤에는 '라' 입니다.
  이름이 표에서 오는 자리에 조사를 붙이면 표가 늘 때 언젠가 틀립니다.

- **값을 안 박았는데 「그 상황이 있다」를 박았다.** 천장 시험이 난이도를 손으로 안 박은 것까지는
  맞았습니다. 대신 *지금 열린 제작법 중 가장 어려운 것 + 20 이 100 아래* 라는
  **콘텐츠에 딸린 사실**을 박았습니다. 서릿쇠 갑옷(90)이 들어와 제작 천장이 110 이 되자,
  `learnBlock` 은 멀쩡한데 시험이 깨졌습니다. 주석이 "값을 박지 않습니다" 라고 경계한
  바로 그것을 한 겹 위에서 밟은 것입니다.
  **콘텐츠에 딸린 사실과 함수의 성질을 한 시험에 섞지 마라.**
  성질은 합성 입력으로 보고(`tests/rpg/learnblock.test.ts`),
  오늘의 사실은 문서에 적습니다(전체설계 6.2.2).

- **한 시험이 두 가지를 주장하고 있었다.** 「난이도 천장에 막히면 ceiling 이라고 말한다」가
  ①`learnBlock` 이 천장 상황에서 그렇게 답하는가(**함수의 성질** — 늘 참이어야 한다)와
  ②오늘 콘텐츠에 그 상황이 실제로 있는가(**사실** — 콘텐츠가 자라면 바뀐다)를
  한꺼번에 보고 있었습니다. 서릿쇠 갑옷(난이도 90)이 들어와 ②가 바뀌자
  **함수는 멀쩡한데 시험이 깨졌습니다.** 성질은 합성 입력으로 떼어내
  `tests/rpg/learnblock.test.ts` 로 옮기고, 사실은 전체설계 6.2.2 에 적었습니다.
  → **값을 안 박았어도 「그 상황이 있다」를 박으면 같은 덫이다.**

- **시험이 재료를 안 보고 장비를 입혔다.** `deep.test.ts` 의 `reachableGear` 가
  「제작법이 열렸는가」만 보고 「재료를 구할 수 있는가」를 안 봤습니다.
  서릿쇠 갑옷은 처음부터 열려 있지만 서릿쇠는 3층에서만 나는데,
  시험은 **2층 문 앞의 사람에게 3층 장비를 입히고** 문턱을 재고 있었습니다.
  제련을 거슬러 밑재료 광석까지 따라가 그 광맥이 어느 지역에 있는지 표에서
  끌어오게 고쳤습니다. → **시험이 세계를 실제보다 넓게 보면 잰 값이 전부 거짓이다.**

- **카메라가 화면 픽셀에 안 맞아 있었다.** 월드 한 칸이 화면에서 `zoom × dpr` 픽셀인데
  1.70 · 2.75 처럼 정수가 아니고, 카메라는 소수로 움직입니다. 그래서 **같은 벽 모서리가
  매 프레임 최대 반 픽셀씩 다른 자리에** 그려졌습니다(실측: 어긋난 프레임 30/30 · 84/84).
  도형이라 아무도 눈치 못 챘지만 그림으로 가면 격자가 뭉개집니다.
  → `view.ts` 의 `snapView`. **`GameScreen` · `draw` · `kick` 셋이 같은 dpr 을 봐야 한다** —
  하나라도 소수가 남으면 스냅이 통째로 헛일이 됩니다.

- **`lighten`/`darken` 이 `#hex` 가 아니라 `rgb(r,g,b)` 를 돌려준다.** 그림에 코드 색을
  입히면서 `parseInt(색.slice(1), 16)` 로 읽었습니다. `'rgb(160,147,125)'.slice(1)` 은
  `'gb(160,147,125)'` 이고 그것을 16진수로 읽으면 **NaN**, `(NaN >> 16) & 255` 는 **0** 입니다.
  **짐승이 전부 새까맣게 그려졌습니다.** 예외도 없고 콘솔도 조용했습니다 —
  숫자가 하나 0 이 됐을 뿐이라 아무 데서도 안 걸립니다.
  화면 픽셀을 직접 세어보고서야 알았습니다(가장 많이 쓰인 색이 `#000000` 1834칸).
  → `packColor` 가 두 꼴을 갈라 읽고, **못 읽으면 던집니다.** 조용히 검정으로 안 떨어지게.
  → **같은 파일 안에서도 색의 표현이 하나가 아니다.** `def.color` 는 hex 인데
  거기서 파생된 `shades()` 의 light·dark 는 rgb() 입니다. 표현이 섞이는 경계를
  넘을 때는 **눈이 아니라 값으로** 확인해야 합니다 (CLAUDE.md 6장).

- **같은 API 안에서 한쪽 출력이 다른 쪽 입력에 그대로 안 들어간다.** PixelLab 의
  `estimate_skeleton` 은 관절의 `z_index` 를 **소수**로 줍니다 (`-3.5`, `-0.5`).
  그런데 `animate_with_skeleton` 은 **정수만** 받아서 그대로 넘기면 `422` 입니다.
  「뽑아서 그대로 넣는다」가 당연해 보여서 검증을 안 하고 넘겼습니다.
  → **남의 API 도 두 함수 사이에 계약이 있다고 가정하지 마라.** 다행히 이건
  시끄럽게 실패했지만(422), 조용히 잘렸으면 관절이 어긋난 채로 그림이 나왔을 것입니다.
