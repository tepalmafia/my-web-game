# 아덴의 그림자 — 완성판 기획 기준선

> 상태: **v0.1 기준선**
> 목적: 현재 프로토타입을 Web·스마트폰에서 완전 플레이 가능한 게임으로 만들고, 같은 게임 코어를 장기적으로 Steam까지 가져가기 위한 **완성판의 상위 설계 기준**을 고정한다.
>
> 이 문서는 세부 구현 순서를 다시 정하지 않는다. **만드는 순서는 `전체설계.md` 10절이 정본**이다.
> ①②③의 정의와 판정 규칙은 **`목적지-기획안.md`가 정본**이다.
> 이 문서는 그 위에 **완성판 규모·콘텐츠 문법·세대 구조·플랫폼 방향**을 얹는다.

---

## 0. 표기 규칙

이 문서의 모든 항목은 다음 네 상태 중 하나로 적는다.

- **[확정]** 뒤집으면 게임의 정체성 또는 이미 검증된 상위 계약이 바뀐다.
- **[가설]** 방향은 유력하지만 플레이 검증 전이다. 숫자는 대체로 여기에 속한다.
- **[미정]** 아직 답을 정하지 않았다. 구현으로 몰래 확정하지 않는다.
- **[실측]** 코드·봇·실제 측정으로 확인된 사실이다. 추정과 섞지 않는다.

### 0.1 문서 간 역할

| 문서 | 역할 |
|---|---|
| `전체설계.md` | 현재 게임의 구조와 **구현 순서** |
| `목적지-기획안.md` | ① 세계가 인정 · ② 기록이 인정 · ③ 세계가 변함 |
| `이야기-기획안.md` | 실버우드 · 두린 · 발도르 · 이야기 |
| `완성판-기획안.md` | **완성판 규모·콘텐츠·세대·플랫폼 기준선** |
| `그림-작업.md` | 아트 자산·실측·생성 파이프라인 |

충돌하면 추측해 합치지 않는다. 무엇이 충돌하는지 보고하고 사람이 결정한다.

# 1. 이 게임은 무엇인가

## 1.1 North Star

**[확정]**

> 한 캐릭터는 세계의 일부만 경험한다.
> 그가 이룬 것은 **세계가 알아보고(①)**,
> 그가 고른 것은 **세계에 남고(③)**,
> 그가 세운 것은 **다음 캐릭터가 넘어선다(②)**.
> 여러 캐릭터의 서로 다른 삶이 겹쳐졌을 때 한 세계가 완성된다.

이 게임의 메타 진행은 **캐릭터가 강해지는 것보다 세계가 두꺼워지는 것**이다.

## 1.2 플레이어가 켰을 때 드는 생각

**[확정]**

> “오늘 나는 이 세계에서 뭘 해볼까.”

이를 위해 이미 정한 세 조건을 유지한다.

1. 서로 포기하는 것이 있는 선택
2. 결과의 불확실성
3. 되돌릴 수 없음

콘텐츠를 늘리는 목적은 플레이 시간을 채우는 것이 아니라 **이 세 조건이 붙는 판단의 수를 늘리는 것**이다.

# 2. 플랫폼과 제품 목표

## 2.1 플랫폼

**[확정]**

1. **Web** — 현재 개발·배포 기준
2. **스마트폰 Web/PWA 계열** — 터치 기준 UI와 세션 구조
3. **Steam** — 같은 게임 코어를 desktop wrapper/adapter로 확장

Steam 때문에 현재 React + Vite + Canvas 구조를 미리 갈아엎지 않는다.

## 2.2 플랫폼 아키텍처 원칙

**[확정]**

```text
게임 코어
├ world
├ combat
├ crafting
├ economy
├ progression
├ recognition ①②③
└ save serialization
       ↓
입력 명령
├ touch
├ mouse/keyboard
└ gamepad
       ↓
표현
├ Canvas world
└ responsive UI
       ↓
배포 adapter
├ Web/PWA
└ Steam desktop
```

- core는 touch/mouse/Steam을 알지 않는다.
- `move`, `attack`, `interact`, `use`, `openInventory` 같은 **게임 명령**을 플랫폼 입력이 호출한다.
- 저장 내용과 저장 장소를 분리한다. core는 serialize/deserialize 가능한 상태를 만든다.
- 모바일에서 가능하도록 **버튼 수를 늘려 전투 깊이를 만드는 방식은 금지**한다.

## 2.3 완성판 플랫폼 요구사항

**[가설 — 후반 요구사항]**

- 키보드/마우스
- 터치
- 게임패드
- Steam Deck 대응
- 저장 슬롯
- Steam Cloud 연결 가능 구조
- UI scale
- 텍스트 크기
- 키 remap
- 오디오 볼륨 분리
- 모바일 background 복귀 안정성
- 접근성/가독성
- 로컬라이제이션 가능한 문자열 구조

지금 모두 구현하지 않는다. **입력 abstraction과 저장 경계만 지금부터 깨지 않게 한다.**

# 3. 게임의 크기

## 3.1 시간 단위

**[확정 — 기존 전체설계와 일치]**

- 세션의 기본 마디는 **하루**다.
- 하루 한두 번 나갔다 돌아오는 플레이가 약 **30~40분**의 세션 단위다.
- 한 캐릭터는 모든 갈래를 끝내지 못한다.

**[가설 — 완성판 목표]**

| 단위 | 목표 |
|---|---:|
| 첫 핵심 경험 | 30분 안 |
| 한 캐릭터 | 약 12~20시간 |
| 한 세계 | 약 3~5 캐릭터 |
| 세계 1회 완주 | 약 40~70시간 |

숫자를 맞추기 위해 반복 작업을 늘리지 않는다. 실제 vertical slice 실측으로 조정한다.

## 3.2 한 캐릭터의 끝과 세계의 끝

**[확정]**

- **한 캐릭터의 끝**: 자기 삶에서 선택한 갈래·목표의 큰 문턱에 도달하고, 그 결과 일부를 세계에 남긴다.
- **세계의 끝**: 여러 캐릭터가 서로 다른 갈래에서 남긴 결과가 누적되어 마지막 물건/마지막 도달로 연결된다.

**[미정]** 마지막 물건의 정확한 제작 조건과 엔딩 조건.

# 4. 세 가지 인정 — 완성판에서의 역할

정의 자체는 `목적지-기획안.md`를 따른다.

## 4.1 ① 세계가 인정한다 — 목적지

**[확정]** 단순 달성 로그가 아니다.

```text
문턱을 넘음
→ 세계가 그 사실을 알아봄
→ 플레이어가 화면에서 그 반응을 봄
→ 다음 판단이 달라짐
```

완성판의 ① 후보는 네 종류다.

- 장소
- 물건
- 실력
- 행위

**[가설 — 규모]** 전체 후보 약 50~70개. 전부 칭호로 만들지 않는다.

세계 반응은 분산한다.

- 칭호
- NPC 반응
- 지도
- 현장 표식
- 새 사건 후보
- 특정 문/행동 가능성

## 4.2 ② 기록이 인정한다 — 역사와 기준

**[확정]** 기록은 업적 메뉴가 아니라 다음 캐릭터의 판단을 바꾸는 세계의 역사다.

세 층을 유지한다.

1. **물건의 이력** — 누가 만들었고 무엇을 했는가
2. **세계/마을의 기록** — 최고 깊이, 최초 발견, 최고 작품, 큰 손실
3. **다음 캐릭터의 기준과 유산** — 넘을 기록, 이어받은 정보와 물건

가능하면 현장에서 보인다.

예:

```text
전 세대 최고 도달선
“라울 — 여기까지”

그 아래
“이 아래부터 기록 없음”
```

## 4.3 ③ 세계가 변한다 — Legacy

**[확정]** 세계가 스스로 변한 것과 플레이어가 남긴 흔적을 구별한다.

### Simulation

- 날씨
- 가격의 자연 변동
- 광맥 회복
- 시간 경과
- 몬스터의 자연 이동

### Legacy = ③ 후보

- 내가 연 통로
- 내가 남긴 검/갑옷
- 내가 걸어둔 증표
- 내가 복구한 장소
- 내가 정착시킨 자원/생물

③은 다음 세 조건을 모두 만족해야 한다.

1. 보인다.
2. 내 행동 때문임을 안다.
3. 다음 판단을 바꾼다.

**[가설]** 한 캐릭터가 남기는 **큰 영구 흔적은 2~4개 정도**가 적절하다. 모든 행동을 영구화하지 않는다.

# 5. 세계 구조

## 5.1 기본 구조

**[확정]** 가로로 맵을 무작정 늘리는 대신 **기존 갈래가 안으로 깊어진다.**

```text
실버우드 마을
├ 숲 계열
├ 강 계열
├ 광산 계열
└ 던전 계열
```

세 자원 갈래와 던전의 성격은 다르다.

- 숲·강·광산: **얻는 곳**
- 던전: **뚫는 곳 / 반복 도전**

## 5.2 완성판 공간 규모

**[가설]**

- 의미 있는 공간: 약 **25~30구역**
- 각 자원 갈래: 약 6~8개의 핵심 구역
- 던전: 3~5종 또는 그에 준하는 반복 구조

“구역 수”는 목표가 아니다. 구역마다 **다른 질문**이 있어야 한다.

## 5.3 숲의 질문

**[가설]** 생명·사냥·벌목.

- 무엇을 벨 것인가
- 무엇과 싸울 것인가
- 희귀 자원을 들고 돌아갈 것인가
- 길을 열면 생태가 어떻게 바뀌는가

후보 흐름:

```text
숲 가장자리
→ 사냥터
→ 버려진 벌목장
→ 깊은 숲
→ 늑대 굴
→ 고목 군락
→ 고목의 자리
```

## 5.4 강의 질문

**[가설]** 시간·수위·짐·낚시.

- 지금 건널 것인가
- 기다릴 것인가
- 무거운 짐으로 위험을 감수할 것인가
- 희귀 개체를 잡을 것인가 남길 것인가

후보 흐름:

```text
강가
→ 얕은 여울
→ 갈대 습지
→ 큰굽이
→ 상류
→ 폭포 아래
→ 침수된 폐허
→ 물이 시작되는 곳
```

## 5.5 광산의 질문

**[확정/가설 혼합]** 무게·장비·깊이가 현재 가장 많이 검증된 갈래다.

후보 완성판 흐름:

```text
폐광 입구
→ 철 작업구역
→ 구리 갱도
→ 2층
→ 검은쇠 구역
→ 3층
→ 서릿쇠 구역
→ 최심부
```

**[실측]** 임의 벽 파기로 의미 있는 장거리 지름길을 만드는 기획은 현재 지도에서 가치가 없었다.
3층·최심부 포함 재측정에서도 의미 있는 20칸+ 지름길은 0개였다.

따라서 광부의 ③은 **[미정]**이다.

유력 후보는 **정해진 영구 굴착 지점**이다.

```text
무너진 옛 갱도
→ 파기 전에는 결과를 모름
→ 희귀 자원 / 다른 층 / 몬스터 구역 / 옛 작업장 등
→ 한 번 열면 영구히 남음
→ 누가 열었는지 표식
```

아직 확정하지 않는다.

# 6. 캐릭터와 세대

## 6.1 직업을 고르지 않는다

**[확정]** 시작할 때 “전사/장인/광부” 버튼으로 직업을 고르지 않는다.

행동, 스킬 예산, 장비, 도구 선택의 결과로 **살아보니 어떤 사람이 되었는가**가 드러난다.

후보 플레이 스타일:

- 검객
- 중장 전사
- 사냥꾼
- 던전 탐험가
- 무기 장인
- 방어구 장인
- 연장 장인
- 광부
- 벌목꾼
- 어부
- 전투+채집 혼합형
- 제작+전투 혼합형

**[가설]** 최소 8~12개의 체감 가능한 플레이 스타일이 나오는 것이 목표.

## 6.2 총합 상한의 목적

**[확정]** 한 캐릭터가 모든 길을 최고까지 가는 것을 막는다.

상한은 플레이어가 **무엇에 자신의 생애 예산을 썼는지**를 남기는 장치다.

## 6.3 세대 전환

**[가설 — 우선 검증 대상]**

```text
새 캐릭터
→ 하루를 반복하며 삶/빌드 형성
→ 큰 ① 도달
→ ③ 흔적 일부 확정
→ 죽음 또는 은퇴
→ ② 기록/유품 정리
→ 다음 캐릭터
```

### 은퇴 = 준비한 계승

후보 규칙:

- 큰 도달을 이룬 뒤 스스로 생애를 닫을 수 있다.
- 대표 유품 1개 지정.
- 마을에 남길 것 확정.
- 마지막 칭호·대표 기록 정리.
- 스킬 수치는 후대에 직접 물려주지 않는다.

### 죽음 = 준비하지 못한 계승

후보 규칙:

- 기존 사망/짐 손실 규칙을 따른다.
- 이미 확정된 ③과 ②는 사라지지 않는다.
- 미리 지정하지 않은 유품/준비는 손실 위험이 있다.

**[미정]** 캐릭터의 자연 수명, 은퇴 가능 정확 조건, 죽음이 곧 세대 종료인지 여부.

## 6.4 캐릭터 정체성

**[가설]** ②가 감정적으로 읽히려면 최소 다음 정보가 필요하다.

- 이름
- 세대 번호
- 외형
- 선택한 칭호
- 대표 기록
- 남긴 물건/흔적
- 마지막 상태

예:

> 3대 라울 · 「아래를 본 사람」 · 최심부 도달 · 47일 · 서릿쇠 검을 남김

# 7. 하루 — 30~40분 세션 문법

**[확정 — 기존 전체설계 기반]**

```text
아침
→ 현재 세계 상태 확인
→ 가방 꾸리기
→ 오늘의 목적지 선택
→ 사냥 / 채집 / 탐험
→ 예상 밖 상황
→ 더 갈지 돌아갈지 판단
→ 귀환
→ 판매 / 제작 / 수리 / 남기기
→ 기록 갱신
→ 다음 날
```

**[가설]** 좋은 세션은 대체로 다음 정도의 판단을 가진다.

- 계획 1회
- 중요한 짐 선택 1~3회
- 예상 밖 상황 1회
- 귀환 여부 판단 1회
- 귀환 후 제작/판매/남기기 1~2회

매 세션 큰 보상을 줄 필요는 없다.

- 2~3세션마다 작은 ① 또는 작은 ③ 후보
- 여러 세션마다 큰 도달
- 한 캐릭터 전체에서 큰 ③ 2~4개

숫자는 vertical slice에서 조정한다.

# 8. 전투 문법

## 8.1 목표

**[확정]** 적의 수가 아니라 **적을 상대하는 판단의 수**를 늘린다.

HP·공격력만 다른 몬스터는 새로운 콘텐츠로 세지 않는다.

## 8.2 기본 입력

**[가설]** 모바일과 Steam을 동시에 만족하기 위해 기본 행동 수를 제한한다.

- 이동
- 공격
- 강공격/차지 또는 이에 준하는 한 가지 보조 공격
- 회피/방어
- 소비품/도구
- 상호작용

## 8.3 몬스터 행동 archetype

**[가설]** 약 8~10개 기본 행동 문법을 조합한다.

- 추격형
- 돌진형
- 무리형
- 방어형
- 매복형
- 견제형
- 영역형
- 약탈형
- 환경형
- 희귀형

## 8.4 무기 문법

**[가설]** 무기는 DPS 숫자보다 싸우는 거리를 바꾼다.

- 단검 — 빠름, 짧음
- 검 — 균형
- 장검/대검 — 느림, 긴 판정/높은 부담
- 도끼 — 경직/벌목과 혼합 가능
- 망치 — 방어/갑각 대응
- 창 — 긴 선형 거리
- 원거리 — 탄약/짐이라는 비용

**[검증 기준]** 최소 3개의 무기 문법과 4개의 적 대응이 실제로 다르게 느껴져야 전체 몬스터를 확장한다.

# 9. 콘텐츠 규모 목표

다음 수치는 **[가설]**이며 제작 할당량이 아니다.

| 콘텐츠 | 현재 프로토타입 | 완성판 목표 범위 |
|---|---:|---:|
| 일반/주요 몬스터 | 7종 수준 | 30~40종 |
| 몬스터 행동 문법 | 적음 | 8~10 archetype |
| 희귀/엘리트/보스 | 적음 | 14~20개 후보 |
| 의미 있는 구역 | 광산 중심 | 25~30 |
| NPC | 소수 | 12~18 |
| 칭호 | 2개 | 30~40 |
| 자원 | 광석 중심 | 25~35 |
| 기본 아이템 definition | 수십 | 100~130 |
| 제작법 | 17개 수준 | 50~70 |
| 세계 사건 | 전용 계층 없음 | 40~60 원형 |
| 마을의 청 | 미구현 | 약 30 원형 |
| 고유 사건 | 적음 | 15~20 |
| 기록 항목 | 거의 없음 | 약 20 |

**[확정]** 목표 수를 채우기 위해 스탯만 다른 콘텐츠를 복제하지 않는다.

# 10. 아이템 설계

## 10.1 아이템의 기본 공식

**[확정]** 수백 개의 고정 아이템을 손으로 만드는 대신 적은 기본형에 실제 이력을 얹는다.

```text
기본형
× 재료
× 품질
× 벼림
× 내구/수리
× 사용 이력
× 제작자
```

아이템의 희귀함은 색깔 등급보다 다음에서 나온다.

- 어디서만 얻을 수 있는가
- 무엇을 포기하고 가져왔는가
- 누가 만들었는가
- 무엇을 해냈는가

## 10.2 아이템 카테고리

**[가설]**

### 자원 — 25~35

후보:

- 철광석/철
- 구리광석/구리
- 검은쇠
- 서릿쇠
- 불꽃쇠
- 일반 목재
- 단단한 목재
- 고목 심재
- 약초/독초
- 가죽/비늘
- 일반/희귀 어류 자원

자원별 비용은 같게 만들지 않는다.

- 무게
- 부피
- 채집 시간
- 도구 소모
- 위험 지역

중 일부가 달라야 한다.

### 무기 — 기본형 약 20~25 후보

단검·검·장검·대검·도끼·망치·창·원거리 등의 문법을 재료/품질과 조합한다.

### 방어구 — 약 18~24 후보

- 가죽 — 가볍지만 낮은 방어
- 사슬 — 균형
- 판금 — 높은 방어, 짐 손해
- 방수/강 특화
- 방한/심층 광산 특화
- 사냥/숲 특화

“특정 지역 입장권”처럼 한 벌이 정답이 되지 않게 한다.

### 도구 — 약 12~16 후보

- 곡괭이
- 벌목도끼
- 낚싯대
- 대장망치
- 등불
- 로프
- 삽/지렛대 등

도구는 스킬의 물리적 비용이다.

### 소비품 — 약 15~20 후보

회복·해독·등불기름·미끼·연마석 등.

소비품을 많이 들면 안전하지만 채집물을 덜 가져와야 한다.

### 유물/고유품 — 약 20~30 후보

발도르의 물건, 갈래 끝 물건, 던전 고유품, 세대 유품 등.

전투력보다 **출처와 역사**가 희귀함을 만든다.

## 10.3 아이템의 생애

**[가설 — ②의 핵심 후보]**

```text
획득/제작
→ 사용
→ 닳음
→ 수리
→ 이력 누적
→ 계속 사용 / 세계에 남김
→ 파손
→ 기록 보존 여부 판정
```

기록 후보:

- 제작자
- 제작 당시 스킬
- 벼림
- 처치 수
- 수리 횟수
- 사용 일수
- 도달한 가장 깊은 장소
- 파손 장소/원인

모든 부러진 물건을 전시하지 않는다. **기록급 물건만 세계의 흔적으로 승격**한다.

# 11. 미션 대신 세계 상황

## 11.1 금지하는 퀘스트 문법

**[확정]**

> “늑대 10마리 잡기 → 골드 100”

같은 체크리스트를 콘텐츠의 주축으로 만들지 않는다.

미션/사건은 발생했을 때 **오늘의 목적지·가방·위험 판단 중 하나 이상을 바꿔야 한다.**

## 11.2 A. 세계 사건

**[가설 — 40~60 원형]**

후보:

- 늑대 떼 이동
- 희귀 몬스터 출현
- 광맥 노출
- 낙석
- 강 수위 변화
- 방랑 상인 방문
- 특정 NPC 부재
- 쓰러진 나무
- 폐허 노출

플레이어가 무시해도 게임은 진행된다.

## 11.3 사건 엔진

**[가설 — 우선 설계 대상]**

```text
하루 시작
→ 세계 상태 확인
→ 사건 후보 생성
→ 0~2개 활성
→ 플레이어가 대응하거나 무시
→ 해결 또는 자연 종료
→ 상태 반영
```

각 사건은 최소 다음 데이터를 가진다.

- 발생 조건
- 지속 기간
- 동시에 존재 가능한지
- 재등장 쿨다운
- 무시했을 때 결과
- 해결했을 때 결과
- Simulation 결과인지 Legacy(③) 후보인지

**[확정]** 플레이어 인벤토리를 읽고 “마침 지금 필요한 것”만 주는 방식으로 세계를 맞춤 생성하지 않는다.

## 11.4 B. 마을의 청

**[가설 — 약 30 원형]**

재료 납품 사다리보다 **완성품·증표·실제 남길 자리**를 중심으로 한다.

후보:

- 경비병 무기
- 경비병 갑옷
- 작업용 연장
- 광장 진열품
- 몬스터 증표
- 갈래 고유 완성품

좋은 청의 구조:

```text
빈 자리/필요 발생
→ 무엇을 원하는지 보임
→ 지금 가진 것을 쓸지 남길지 고민
→ 남기거나 보류
→ 자리가 실제로 바뀜
→ 후대 판단이 달라짐
```

**[미정]**

- 청 발생 조건
- 동시 개수
- 유지 기간
- 교체 시점
- 사라진 청 재등장 여부
- 놓쳤을 때 정확히 무엇을 잃는가

이 값이 정해지기 전에는 대규모 청 콘텐츠를 만들지 않는다.

## 11.5 C. 기록 도전

**[가설 — 약 20항목]**

예:

- 전 세대 최고 공격력 검
- 가장 깊은 장소
- 하루 최대 운반량
- 최고 던전 방
- 가장 오래 쓴 장비
- 가장 큰 손실

기록이 플레이어를 위험한 선택으로 밀어야 한다.

```text
현재 안전한 결과 32
전 세대 기록 34
→ 안전하게 쓸까
→ 실패 위험을 감수하고 35를 노릴까
```

## 11.6 D. 고유 사건

**[가설 — 15~20]**

발도르, 각 갈래 끝, 중요한 유물, 첫 던전 마지막 방처럼 세계의 큰 이야기와 연결되는 일회성 사건.

# 12. NPC와 마을

## 12.1 마을의 역할

**[확정]** 마을은 progression bar를 채워 제작법을 주는 곳이 아니다.

> **주는 곳이 아니라, 앞선 캐릭터가 남긴 것이 보이는 곳.**

마을 자체가 세대의 물리적 UI가 된다.

- 성문 — 전사의 증표
- 경비병 — 이전 장인이 만든 장비
- 광장 — 중요 작품/유물
- 대장간 — 발도르와 제작 기록
- 지도 — 발견과 열린 길
- 기록판 — 세계 기록

## 12.2 NPC 역할망

**[가설]** NPC 12~18명을 무작정 늘리지 않는다. 각 NPC가 하나 이상의 인정 기능을 책임진다.

예:

| NPC 역할 | ① | ③ | ② |
|---|---|---|---|
| 두린/대장장이 | 제작 성취를 알아봄 | 작품 보관/사용 | 과거 장인과 물건 이력 |
| 경비대장 | 전투 성취 | 증표/순찰 변화 | 전사 기록 |
| 벌목꾼 | 숲 도달 | 벌목장/길 | 이전 벌목 기록 |
| 어부 | 강 도달 | 어종/수변 변화 | 희귀 어종 기록 |
| 지도 제작자 | 발견 | 지도 갱신 | 최초 발견자 |
| 기록지기 | — | — | 세대 기록과 연대기 |

NPC는 보상 자판기보다 **세계가 플레이어를 알아보는 입**이다.

# 13. 전사·장인·채집가가 남기는 ③

## 13.1 전사

**[가설]** 몬스터 증표/생태 변화.

예:

- 성문에 걸 수 있는 증표 슬롯은 제한.
- 어떤 종의 증표를 걸지 선택.
- 그 종이 마을 주변에서 줄어듦.
- 빈 생태 자리를 다른 종이 일부 차지할 수 있음.

핵심은 “게임을 쉬워지게 만든다”가 아니라 **어떤 세계를 만들지 고른다**다.

## 13.2 장인

**[가설]** NPC가 실제로 사용하는 물건.

예:

- 경비병 검 자리에 내 검을 남김.
- 경비병이 그 검을 실제로 들고 다님.
- 해당 NPC의 행동/순찰 또는 그 주변의 위험이 일부 바뀜.
- 그 물리적 자리는 이미 채워졌으므로 후대는 다른 남기기를 고민.

그림만 바뀌면 ③이 아니라 장식이다.

## 13.3 광부

**[미정]** 임의 벽 파기는 현재 실측으로 가치가 없었다.

유력 후보: **영구 굴착 지점**.

최종 결정 전까지 “광부의 ③을 채우기 위해” 임시 시스템을 넣지 않는다.

## 13.4 벌목꾼

**[가설]** 특정 고목/장애물을 제거해 영구 경로를 여는 대신 생태도 연결.

편의만 생기면 부족하다. 새로운 위험/자원 흐름도 같이 바뀌어야 한다.

## 13.5 어부

**[가설]** 일부 희귀 개체/번식 자원을 잡을지 되돌릴지 선택.

놓아준 결과가 후대의 어종·자원·현장에 남고 “누가 시작했는지” 보이면 ②+③ 후보가 된다.

# 14. 경제

## 14.1 골드 source / sink

**[가설]**

### Source

- 몬스터
- 판매
- 일부 사건
- 고유 보상

### Sink

- 도구
- 수리
- 소비품
- 지도/정보 서비스
- 임시 서비스
- 원정 준비

**[확정]** 골드를 마을 단계 bar에 붓는 구조는 되살리지 않는다.

돈은 “현재 캐릭터가 무엇을 준비하고 무엇을 포기할지”에 쓰인다.

## 14.2 가격 변화

가격은 Simulation일 수 있다.

③으로 세려면 플레이어의 판매/행동이 원인임을 알아볼 수 있고 다음 판단을 바꿔야 한다.

**[가설]** 시장군 8~12개 정도로 묶고 변동 폭을 제한해 단일 최적 파밍이 생기지 않게 한다.

# 15. 정보와 발견

**[가설]** 정보 자체도 세대가 쌓는 자원이다.

```text
미지
→ 소문/징후
→ 대략 위치
→ 직접 발견
→ 정확한 지도 정보
→ 후대에 계승
```

대상 후보:

- 광맥
- 희귀 몬스터 영역
- 숨은 여울
- 던전 입구
- 폐허
- 영구 굴착 지점

**[확정]** 처음부터 모든 정보를 지도/위키처럼 보여주지 않는다.

②의 일부는 **후대가 앞사람보다 더 많은 것을 알고 시작하는 것**이다.

# 16. 스토리 척추

## 16.1 원칙

**[확정]** 한 캐릭터가 모든 진실을 알 수 없어야 세대 구조와 이야기가 맞는다.

긴 컷신보다 여러 세대가 물건·장소·기록으로 조각을 발견한다.

## 16.2 최소 서사 뼈대

**[가설]**

1. 1세대 — 광산과 발도르에 대한 의문
2. 이후 세대 — 숲에도 비슷한 흔적 발견
3. 이후 세대 — 강에도 같은 원인의 흔적 발견
4. 세 갈래의 끝 — 서로 다른 조각이 하나의 과거로 연결
5. 마지막 물건/세계 끝 — 앞 세대들이 남긴 결과의 의미가 드러남

**[미정]** 정확한 과거 사건, 최종 적/원인, 마지막 물건의 서사적 의미.

# 17. 세계 엔딩과 새 세계

**[가설]** 마지막 도달 뒤에는 “보상 화면”보다 **세계 연대기**가 결론이어야 한다.

연대기 후보:

- 세대별 이름
- 대표 칭호
- 갈래
- 큰 ①
- 큰 ③
- 대표 물건
- 최고 기록
- 가장 큰 손실
- 마지막 상태

그 뒤 선택 후보:

- 완성된 세계 계속 플레이
- 새 seed 세계 시작

**[미정]** 새 세계가 이전 세계의 무엇을 계정 차원에서 기억하는가.

# 18. 첫 완성판 밀도 검증 — 숲 Vertical Slice

## 18.1 왜 숲인가

**[가설]** 광산은 지금까지 시스템 검증에 가장 많이 사용됐다.
다음 확장에서는 새 갈래인 숲 하나를 **완성판 콘텐츠 밀도**로 만들어야 문법이 다른 지역에도 통하는지 알 수 있다.

## 18.2 목표

다음은 **목표 범위**이지 작업 할당량이 아니다.

| 항목 | 숲 slice 후보 |
|---|---:|
| 플레이 | 5~8시간 |
| 구역 | 5~7 |
| 일반 몬스터 | 약 8 |
| 희귀/보스 | 2 + 1 |
| 자원 | 약 8 |
| 제작 연결 | 약 10 |
| 세계 사건 | 8~10 |
| 마을의 청 | 약 5 |
| ① 후보 | 약 8 |
| ② 기록 | 약 4 |
| ③ 큰 변화 | 약 3 |

## 18.4 Vertical Slice 통과 조건

**[확정 — 검증 원칙]**

숲 하나가 실제로 다음을 만들지 못하면 강·광산 전체 콘텐츠를 대량 생산하지 않는다.

- “오늘 어디로 갈까”가 반복해서 달라짐
- 전투형/벌목형/혼합형 캐릭터가 서로 다른 준비를 함
- 작은 ①·③이 몇 세션마다 나타남
- ②가 다음 캐릭터의 판단을 실제로 바꿈
- 모바일 입력 수를 늘리지 않고도 전투/탐험 차이가 남

실패하면 **숲에서 고치고**, 30개 지역을 만든 뒤 고치지 않는다.

# 20. 개발 시 지켜야 할 절단선

## 20.1 콘텐츠를 대량 생산하기 전

**[확정]**

1. 상위 계약을 읽는다.
2. 새 콘텐츠가 어떤 판단을 추가하는지 한 줄로 말할 수 있어야 한다.
3. 그 판단이 없다면 스탯/외형만 다른 복제 콘텐츠로 본다.
4. 새 시스템 원형은 작은 vertical slice에서 검증한다.
5. 2번 같은 접근이 실패하면 세 번째로 반복하지 않는다.

## 20.2 숫자는 목표이지 의무가 아니다

**[확정]**

- 몬스터 30~40
- 아이템 100~130
- 사건 40~60
- 칭호 30~40

등은 **Steam 규모를 가늠하는 목표 범위**다.

숫자를 채우느라 판단이 없는 콘텐츠를 만들면 실패다.
