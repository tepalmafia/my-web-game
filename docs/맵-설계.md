# 0. 상태 표기

- **[확정]** 기존 상위 계약 또는 아키텍처 불변조건에서 이미 정해진 것
- **[가설]** 레벨 디자인 후보. 실제 플레이 검증 전
- **[미정]** 아직 사람의 결정이 필요한 것
- **[실측]** 현재 브랜치 문서/코드/측정으로 확인되는 것

문서끼리 충돌하면 이 문서가 임의로 우선하지 않는다. 충돌 지점을 보고하고 결정받는다.

# 1. 맵이 해야 하는 일

## 1.1 맵은 배경이 아니라 판단을 만드는 구조다

**[확정]** 새 지역은 모양만 달라서는 안 된다.

한 맵을 다른 맵과 구분하는 기준은:

> **이 맵에서 반복해서 하게 되는 질문이 무엇인가.**

이다.

예:

- 숲 가장자리 — 오늘 무엇을 할지 고르는 곳
- 사냥터 — 빠른 위험길과 느린 안전길을 고르는 곳
- 깊은 숲 — 길을 알고 있느냐가 가치인 곳
- 늑대 굴 — 전투에 투자한 캐릭터가 선택해서 들어가는 곳
- 고목 군락 — 시간·짐·벌목을 한 번에 거는 곳
- 강 — 어느 길보다 **언제, 어떤 짐으로 건널지**가 중요한 곳
- 광산 — 무게·장비·깊이를 감수하는 곳
- 던전 — 돌아갈 수 없는 불확실한 방을 얼마나 더 뚫을지 고르는 곳

## 1.2 맵도 재미의 세 조건을 가진다

**[확정]** 각 주요 구역은 가능한 한 다음 세 조건 중 둘 이상을 공간 자체로 만들어야 한다.

1. 선택지가 둘 이상이고 서로 포기하는 것이 있다
2. 결과가 불확실하다
3. 되돌릴 수 없는 결과가 있다

모든 타일마다 셋을 넣지 않는다. 중요한 분기와 socket에 집중한다.

# 2. 큰 원칙 — Authored Topology + Seeded Contents

## 2.1 큰 topology는 의도적으로 만든다

**[가설 — 핵심]**

중요한 연결 구조는 설계자가 보장한다.

- 입구와 출구
- 핵심 랜드마크
- 안전 경로 / 위험 경로
- 큰 우회
- 갈래 문턱
- ① 도달 지점
- ③ Legacy socket
- ② 기록이 보일 자리

특히 **③이 topology를 바꾸는 자리는 우연한 절차생성 결과에 맡기지 않는다.**

절차생성된 벽 수백 개 중 하나가 우연히 가치 있는 지름길이 되기를 기대하지 않는다.

## 2.2 작은 내용은 seed가 바꾼다

**[확정/가설 혼합]** seeded RNG 원칙은 유지한다.

seed가 바꾸기 좋은 것:

- 몬스터 종류와 수
- 자원 위치와 수량
- 작은 장애물
- 일부 샛길의 열림/닫힘
- 사건 발생 socket
- 희귀 개체
- 채집 pocket의 내용
- 장식과 작은 지형 변주

같은 세계 seed에서는 같은 기본 세계가 나와야 한다.

## 2.3 전체 타일맵을 저장하지 않는다

**[확정 — `CLAUDE.md` 아키텍처 불변조건]**

> 지형 자체를 저장하지 않는다.

따라서 영구 변화는 전체 map snapshot을 저장하는 방식으로 해결하지 않는다.

후보 구조:

```text
world seed
+
legacy state
+
현재 simulation state
=
현재 세대가 보는 지도
```

예:

```text
legacy:
  forest_hunt_log_shortcut = true
  forest_logging_camp_restored = true
  mine_old_tunnel_opened = false
```

**[가설]** 실제 save schema와 id는 구현 시 결정한다.

# 3. Zone Template

## 3.1 모든 구역에 필요한 자리

**[가설]** 모든 맵에 무조건 똑같이 9개를 넣는 규칙은 아니다. 다만 설계할 때 다음 후보를 점검한다.

| 자리 | 역할 |
|---|---|
| 입구 | 귀환 기준점 · 이전 구역과 연결 |
| 랜드마크 | 플레이어가 좌표가 아니라 모양으로 현재 위치를 기억 |
| 안전 경로 | 느리거나 보상이 적지만 예측 가능 |
| 위험 경로 | 짧거나 보상이 크지만 전투/환경 위험 |
| 자원 pocket | 짐과 체류시간 판단 |
| 전투 pocket | 싸울지 우회할지 판단 |
| 사건 socket | seed/일자에 따라 다른 상황 발생 |
| Legacy socket | 플레이어 선택으로 후대 topology/상태가 달라지는 자리 |
| 도달/출구 | 다음 구역 또는 큰 ① 문턱 |

## 3.2 기본 모양

**[가설]**

```text
                       [희귀 보상 / side pocket]
                              │
                          위험 샛길
                              │
입구 ── 안전 경로 ── [중심 랜드마크] ── 깊은 지역 ── 다음 구역
 │                         │                    │
초급 자원                사건 socket          ① 문턱
 │                         │                    │
 └────── 긴 우회 ──────────┘               Legacy socket
                                                 │
                                              ② 표식
```

맵마다 이 그림을 그대로 복사하지 않는다. 각 지역의 질문에 맞게 변형한다.

# 4. 경로 설계

## 4.1 길은 최소 두 종류의 비용을 가져야 한다

**[가설]** 의미 있는 분기에서는 다음 중 서로 다른 비용을 붙인다.

- 시간
- 전투 위험
- 독/수위/추위 같은 환경 위험
- 도구 내구
- 소비품
- 짐 공간
- 정보 부족
- 되돌아오는 거리

예:

```text
A. 안전길
  + 전투 적음
  - 2배 멂

B. 위험길
  + 짧음
  + 희귀 자원 가능
  - 늑대 영역
```

단순히 왼쪽/오른쪽인데 결과가 같은 분기는 만들지 않는다.

## 4.2 모든 맵에 두 길이 필요한 것은 아니다

**[확정]** 구역의 질문이 다른 경우 억지 분기를 만들지 않는다.

예:

- 강은 길보다 수위와 짐이 핵심일 수 있다.
- 고목 군락은 갈림길보다 한 번의 긴 벌목과 귀환 판단이 핵심일 수 있다.
- 던전은 매 방의 전진/후퇴 자체가 핵심일 수 있다.

---

# 5. 랜드마크

## 5.1 플레이어는 미니맵 좌표보다 모양으로 기억해야 한다

**[가설]** 핵심 구역에는 화면에서 바로 구분되는 랜드마크 하나 이상을 둔다.

후보:

- 거대한 바위
- 부러진 고목
- 버려진 수레
- 오래된 작업장
- 특이한 폭포
- 무너진 다리
- 거대한 광맥/지층
- 오래된 석주

랜드마크는 장식만이 아니라 경로 설명에 쓰여야 한다.

예:

> “큰 바위에서 북쪽으로 가면 늑대 영역.”

## 5.2 ②도 랜드마크에 붙을 수 있다

**[가설]**

```text
쓰러진 고목이 있던 자리
→ 2대 하렌이 길을 엶
→ 후대에는 잘린 밑동 + 이름 표식
```

이렇게 하면 ②가 기록 메뉴가 아니라 이동 중에 보인다.

# 6. ①②③ Map Socket

## 6.1 ① Recognition socket

**[확정]** 도달이 의미 있으려면 보이는 문턱과 세계 반응이 있어야 한다.

후보 자리:

- 처음 보는 경계석
- 구역 끝 거대한 자연물
- 봉인문
- 오래된 작업장
- 특정 지형을 내려다보는 전망점
- 갈래 끝의 재료/물건

## 6.2 ③ Legacy socket

**[확정]** ③은 다음을 모두 만족해야 한다.

1. 보인다
2. 내 행동 때문임을 안다
3. 다음 판단을 바꾼다

**[가설]** 맵에서 큰 ③은 개방형 socket으로 미리 자리만 보장한다.

예:

- 쓰러진 고목
- 부서진 다리
- 무너진 옛 갱도
- 폐쇄된 작업장
- 생태를 바꾸는 증표 자리

`Legacy socket = 무조건 활성화할 업그레이드`가 아니다.
활성화하지 않는 선택도 있어야 한다.

## 6.3 ② Record socket

**[가설]** 기록은 결정 지점에서 보인다.

예:

```text
[최심부 경계]
“2대 라울 — 여기까지”

그 아래
“이 아래부터 기록 없음”
```

또는:

- 잘린 고목의 밑동
- 수리된 다리의 명판
- 마을 지도
- 오래된 캠프
- 보스 증표

# 7. 크기와 이동시간

## 7.1 현재는 수치 확정 금지

**[미정]** 숲/강의 실제 map width·height는 아직 결정하지 않는다.

**[가설 — 첫 시험 범위]**

- 일반 구역: 약 44×36 ~ 52×44 수준에서 시험
- 핵심 구역: 약 56×44 ~ 64×48 수준까지 시험

이 숫자는 `맵은 이 크기여야 한다`는 계약이 아니다.

## 7.2 타일 수보다 실제 이동시간을 잰다

**[가설]** 첫 목표:

- 입구 → 출구 직행: 약 1~2분
- 채집/전투/사건 포함 체류: 약 5~12분

하루 30~40분 세션에서 2~4개 구역을 경험할 수 있는지를 본다.

실제 속도·전투·가방 운영을 넣어 측정한 뒤 조정한다.

# 8. 숲 — 실제 세부 topology 후보

> 이하 숲 이름·구역 수·구체 연결은 전부 **[가설]**이다.

전체 후보:

```text
실버우드
  ↓
숲 가장자리
  ↓
사냥터
  ├─ 늑대 굴 (side)
  ↓
버려진 벌목장
  ↓
깊은 숲
  ↓
고목 군락
  ↓
고목의 자리 ★
```

실제 연결은 일직선으로 만들지 않는다. 아래처럼 side area와 우회가 섞인다.

---

## 8.1 숲 가장자리 — “오늘 뭘 할까”

목적:

- 첫 진입에서도 길을 읽기 쉽다.
- 전투/벌목/약초/더 깊이 중 오늘의 방향을 정한다.

후보 구조:

```text
                 [약초밭]
                    │
              ┌─────┘
              │
[마을] ─── [큰 바위] ───── [사냥터 출구]
              │
              │
         [초급 목재]
              │
        [버려진 수레]
```

### Landmark

- 큰 바위
- 버려진 수레

### 전투

- 들개 등 선택 가능한 초급 적

### 자원

- 초급 목재
- 약초

### ③

큰 영구 변화는 두지 않는 후보가 우선이다.

이유: 첫 구역부터 세계를 영구 변경하게 하면 ③의 희소성이 약해진다.

---

## 8.2 사냥터 — “위험한 지름길인가, 긴 안전길인가”

후보 구조:

```text
                    [늑대 영역]
                    /        \
                   /          \
             위험한 길      긴 안전길
                 │              │
                 │              │
[입구] ── [쓰러진 고목] ── [사냥터 중심]
                 │              │
                 │          [가죽/약초]
                 │
             Legacy socket
              고목 제거
                 │
             새 지름길
```

### 질문

- 늑대 영역을 지나 시간을 아낄 것인가
- 안전하게 돌아갈 것인가
- 벌목 캐릭터가 영구 지름길을 열 것인가

### ③ 후보

`쓰러진 고목 제거`

전:

```text
입구 → 긴 우회 → 중심
```

후:

```text
입구 ─────→ 중심
```

### ② 후보

잘린 밑동/표식에 누가 길을 열었는지 남는다.

### 검증

지름길은 실제 왕복 시간과 다음 세대의 목적지 선택을 바꿔야 한다.
몇 초 줄어드는 수준이면 ③으로 채택하지 않는다.

---

## 8.3 버려진 벌목장 — “복구할 것인가 그냥 지나갈 것인가”

후보 구조:

```text
                 [깊은 숲]
                     ↑
                     │
          ┌──── [벌목장] ────┐
          │          │        │
       [창고]      [작업대] [무너진 집]
          │                   │
        자원                사건 socket
          │
        입구
```

### 역할

전투 중심이 아니라 결정 hub.

### ③ 후보

벌목장 복구.

가능한 효과 후보:

- 벌목 관련 NPC가 머문다
- 제한적인 도구 수리 가능
- 일부 숲 정보가 보인다
- 사건 pool이 바뀐다

### 반드시 필요한 손해

**[미정]** 복구가 무조건 이득이면 progression upgrade가 된다.

후보 trade-off:

- 주변 벌목 증가 → 희귀 동물 감소
- 특정 사건이 사라지고 다른 사건이 열림
- 한 번 복구하면 자연 상태로 되돌릴 수 없음

정확한 효과는 아직 정하지 않는다.

---

## 8.4 깊은 숲 — “길을 알고 있느냐”

후보 구조:

```text
                    [희귀 동물]
                        │
               ┌── 숨은 길 ──┐
               │              │
[입구] ── [고목 A] ── [숲 중심] ── [고목 B] ── [고목 군락]
               │              │
            독초 지역      늑대 순찰
               │              │
               └── 긴 우회 ──┘
```

### 질문

- 짧은 길을 알고 있는가
- 독/전투를 감수하는가
- 희귀 동물을 쫓아 오늘 목적을 바꾸는가

### 정보 설계

첫 세대:

- 일부 길은 지도에 없음
- 소문/흔적만 보임

발견 후:

- 정확한 지도 정보로 남음
- 후대는 더 많은 정보를 갖고 시작

### ②

정보 자체가 계승되는 후보.

---

## 8.5 늑대 굴 — “전투에 투자한 캐릭터가 선택하는 side challenge”

후보 구조:

```text
              [우두머리 자리]
                 /      \
              좁은 길    우회
                │         │
            [새끼굴]  [시체/전리품]
                │         │
                └── [큰 굴] ── 입구
```

### 원칙

모든 캐릭터가 들어갈 필요 없다.

### 질문

- 전투 장비를 챙겨 side area에 들어갈 것인가
- 깊이 들어가 퇴로를 길게 만들 것인가
- 증표를 가져오기 위해 다른 자원을 포기할 것인가

### 보상 후보

단순 고성능 무기보다:

- 전사 ③에 쓰는 증표
- 희귀 가죽
- 기록 대상

을 우선 검토한다.

---

## 8.6 고목 군락 — “시간과 짐을 벌목에 건다”

후보 구조:

```text
              [고목의 자리 문턱]
                       │
            ┌───── [대고목] ─────┐
            │                     │
        희귀 목재              안전지대
            │                     │
     [벌목 위험 구역]        [오래된 표식]
            │                     │
            └────── [입구] ───────┘
```

### 질문

- 오래 걸리는 벌목을 지금 시작할 것인가
- 나무를 들고 나오기 위해 다른 짐을 버릴 것인가
- 소음/시간 때문에 생기는 위험을 감수할 것인가

### 문턱

`벌목 스킬 N 필요` 하나로 끝내지 않는다.

스킬 + 도구 + 시간 + 운반이 함께 비용이 되어야 한다.

## 8.7 고목의 자리 — “숲 한 생애의 끝”

후보 구조:

```text
                 오래된 씨앗
                      ★
                      │
              ┌──── [고목] ────┐
              │                │
          오래된 기록       수호자 영역
              │                │
              └──────┬─────────┘
                     │
                  입구 문턱
```

### ①

고목의 자리 최초 도달.

### 갈래 끝 재료 후보

- 오래된 씨앗
- 고목 심재

정확한 최종 재료는 기존 `목적지-기획안.md`와 충돌 없이 나중에 확정한다.

### ③ 후보

갈래 끝에서 무엇을 가져가고 무엇을 남길지 선택.

예:

- 씨앗을 가져감
- 일부를 현장에 남김

정확한 후대 효과는 **[미정]**.

### ②

이전 캐릭터의 첫 도달/선택을 현장에서 읽는 후보.

# 9. 강 — 숲의 길 문법을 복제하지 않는다

## 9.1 강의 핵심 질문

**[가설]**

> 어느 길인가보다 **언제, 어떤 짐으로 건널 것인가.**

강은 다음 변수로 차별화한다.

- 수위
- 건널 수 있는 지점
- 짐 무게
- 이동속도
- 낚시 시간
- 돌아오는 시각

## 9.2 기본 단면 후보

```text
북쪽 둑
────────────────────────

       A 얕은 여울
          ≋ ≋ ≋
            │
         중앙 섬
            │
          ≋ ≋ ≋
       B 깊은 여울

────────────────────────
남쪽 둑
```

A:

- 멀지만 안전

B:

- 빠르지만 깊음
- 무거운 짐이면 위험 증가
- 특정 수위에는 통과 불가

## 9.3 큰굽이 후보

```text
                 [상류]
                    ↑
────────────────────────── 강
          ≋             ≋
      위험한 여울      부서진 다리
          │               │
      [남쪽길]         Legacy socket
          │               │
          └──── [큰굽이] ─┘
                    │
                  입구
```

### ③ 후보

부서진 다리 복구.

하지만 단순 편의 shortcut으로 끝내지 않는다.

후보 결과:

- 상류 접근법 변화
- NPC 이동 가능성 변화
- 낚시/사건 pool 일부 변화

정확한 trade-off는 **[미정]**.

# 10. 광산 — 임의 벽보다 의도된 topology 변화

## 10.1 현재 확인된 실측

**[실측 — `목적지-기획안.md` 3.2]**

현재 브랜치 문서가 공식적으로 확인하는 것은:

- C2' 시점
- 광산 44×40
- 세 층 벽 504개 검사
- 20칸 이상 지름길 0개
- 가장 좋은 벽의 절감 14.6칸

3층·최심부 포함 별도 재측정 수치는 이 문서에서 새로 주장하지 않는다.

## 10.2 문제

현재 광산은 방향성 있는 복도망보다 큰 방에 가까워, 벽 하나를 뚫어도 이미 옆에 우회로가 있다.

따라서:

> 임의 벽을 파면 언젠가 중요한 길이 생기겠지

를 광부 ③의 전제로 삼지 않는다.

## 10.3 후보 구조

**[가설]**

```text
                  [희귀 광맥]
                       │
                 붕괴 지점 ③?
                       │
[입구] ── [작업장] ── [주 갱도] ── [다음 층]
              │           │
           옛 광맥      몬스터 굴
              │           │
              └── 긴 우회 ┘
```

중요한 topology 변화가 필요하면 **의도된 붕괴/굴착 socket**을 만든다.

## 10.4 광부 ③은 아직 미정

**[미정]** 영구 굴착 socket은 유력 후보일 뿐 확정이 아니다.

후보 결과:

- 희귀 자원 공간
- 다른 층과 연결
- 몬스터 구역 개방
- 옛 작업장 발견
- shortcut

중 하나가 될 수 있다.

`무엇이 나올지 모른다`는 불확실성을 줄 수 있지만, 결과 pool과 영구성은 구현 전 별도 설계가 필요하다.

# 12. Event Socket

## 12.1 사건을 아무 타일에 뿌리지 않는다

**[가설]** 사건은 지형과 의미가 맞는 socket에서만 후보가 된다.

이렇게 해야 사건이 UI 알림이 아니라 실제 공간을 바꾼다.

# 13. 자원 배치

## 13.1 균일 분산 금지

**[가설]** 자원을 맵 전역에 같은 확률로 뿌리지 않는다.

자원 pocket을 두어:

- 위험 pocket
- 귀환길에서 먼 pocket
- 특정 도구가 필요한 pocket
- 환경 조건이 필요한 pocket

으로 나눈다.

목적은:

> 어디서 몇 개 캘까

가 아니라:

> 저 pocket까지 들어가면 오늘 돌아올 수 있을까

를 만드는 것이다.

# 14. 몬스터 배치

## 14.1 spawn은 경로 판단과 연결한다

**[가설]**

몬스터를 단순 랜덤 분산하지 않는다.

후보 역할:

- 안전길을 느리게 만드는 약한 적
- 빠른 길을 지키는 강한 적
- 자원 pocket 주변 영역형 적
- 우회 가능한 무리
- 특정 시간에만 이동하는 적
- 희귀 side challenge

몬스터가 있는 이유를 경로/자원/사건 중 하나와 연결한다.

# 17. 검증 방법

## 17.1 topology 검증

**[가설]** 새 Legacy shortcut은 최소 다음을 잰다.

- 활성화 전 입구↔목표 최단거리
- 활성화 후 최단거리
- 실제 게임 이동시간 차이
- 왕복 시간 차이
- 다음 세대의 목적지 선택 변화

단순 타일 절감만으로 성공 판정하지 않는다.

## 17.2 경로 선택 검증

플레이 테스트에서:

- 항상 같은 길만 고르는가
- 위험길이 사실상 정답인가
- 안전길이 사실상 정답인가
- 자원 때문에 계획이 바뀌는가
- 귀환 시 다른 길을 고르는가

를 본다.

## 17.3 랜드마크 검증

미니맵 없이도:

> “큰 바위에서 북쪽”

처럼 설명할 수 있는지 본다.

## 17.4 ③ 검증

기존 판정 그대로:

- 보인다
- 내 탓임을 안다
- 다음 판단을 바꾼다

셋 중 하나라도 빠지면 Legacy socket이라고 부르지 않는다.
